# ProbCrew v2 · 概率论伴学助手

> **一个主站形态的 AI 伴学助手**：学生登录后提问、刷题、看错题本与知识图谱；
> 答疑链路用 LangGraph 编排，解答带**可验证的正确性声明**（这次验证到什么程度），
> 判定链路**不调用任何模型**（确定性代码，< 1s）。
>
> 技术栈：LangGraph 编排 + FastAPI + **免构建 ESM** 前端（零 npm / 零外部 CDN）+ SymPy。
> 模型凭据与端点**由用户自己提供**（N14），因此不存在部署级的共享密钥。

## 现在能不能跑起来？

**不能。** 这不是缺陷，是**阶段划分**：阶段 A 只产出**文档与契约**，`backend/` 与 `frontend/` 的实现代码属**阶段门 B**（[`docs/06`](docs/06-开发计划与阶段门.md) §4）。

★ **为什么先把文档做完**：上一个仓库的实测结论是"**最热的问答接口、统一错误体、分页、作答、掌握度全无契约，每端各写各的形状**"，以及"**引擎有、通路无**"（判定引擎 521 行 / 16 项测试通过，而全仓 21 个路由里**没有一个批改端点**）。所以 v2 的顺序是：**契约先冻结，两边照着写**。

**`docs/07` §2.2 有一张"未产出清单"**，逐个列出还不存在的脚本与资产 —— 想确认某个东西该不该存在，看那张表。

## 门禁与 CI

**本地门禁**：`scripts/verify.sh`（阶段 B 产出）—— 它同时是 R-A/R-B 的静态扫描、依赖方向检查、**R-P 文档自洽检查**的入口。
**远端 CI**：`.github/workflows/ci.yml` 的步骤表与之同源；★ **本仓目前没有配置远端**，因此 CI 尚未实际运行（`docs/07` §2.2 已登记）。

★ **本仓的门禁不接受"静默通过"**：契约校验必须让**示例真的过一遍自己的校验**、文档计数必须**从表体算出来**而不是手写 —— 这两条各自的失败形态（"校验静默通过"与"正文数字没跟表体走"）都已经在本仓真实发生过。
