## 2. 领域模型

### 2.1 名词与职责

| 名词 | 是什么 | 归属层 | 谁产出 |
|---|---|---|---|
| **知识点**（KnowledgePoint） | 依赖图的一个节点，如"条件概率" | `domain`（纯数据） | **内容资产**（F20） |
| **依赖 DAG** | 知识点之间的有向无环关系（前置 → 后继） | `domain` | **内容资产**（F19 要求无环） |
| **题型**（ProblemType） | 一类题的解法套路，如"贝叶斯公式正向代入" | `domain` | **内容资产**（F20，F17 的"适用模型"吃它） |
| **题目**（Problem） | 题干 + 标准答案 + 知识点标注 + 题型 + 难度 | **内容资产** | F20 |
| **错因模式**（MistakePattern） | 一种可枚举的错误，如"方向颠倒" | **内容资产** | F20（F5 吃它） |
| **公式条目**（FormulaEntry） | 定理 / 公式 + **适用条件** + 反例 | **内容资产** | F20（F18 吃它） |
| **作答**（Attempt） | 一次提交：答案、对错、知识点、用时、提示次数 | `learning` | 学生提交 → 判定 |
| **掌握度**（Mastery） | `(user, 知识点)` 的聚合：作答数 / 正确数 | `learning` | 由作答累加 |
| **验证报告**（VerificationReport） | 这次解答验证到什么程度（级别 + 逐项检查 + 置信度） | `graph`（验证节点） | 每条解答必带（F3） |
| **提示**（Hint） | 分级提示的一级（方向 / 步骤 / 解析） | `domain` + `learning` | 分级给出 → 计入 `hint_used` |
| **内容版本**（content_rev） | 五类资产各自的 rev 组合出的**单一版本号** | `domain` | 生成物 `MANIFEST.json` |

### 2.2 知识点 DAG（F19 的核心）

```
            ┌────────────┐
            │ 样本空间与 │
            │  事件运算   │
            └─────┬──────┘
                  │
        ┌─────────┴─────────┐
        ▼                   ▼
  ┌──────────┐        ┌──────────┐
  │ 条件概率  │        │ 独立性   │
  └────┬─────┘        └────┬─────┘
       │                   │
       ├─────────┬─────────┘
       ▼         ▼
  ┌─────────┐ ┌──────────┐
  │ 全概率   │ │ 贝叶斯公式│
  └────┬────┘ └─────┬────┘
       └──────┬─────┘
              ▼
        ┌──────────┐        ┌──────────┐
        │ 随机变量  │───────▶│ 期望     │
        └──────────┘        └────┬─────┘
                                 ▼
                            ┌──────────┐
                            │ 方差     │
                            └──────────┘
```

（示意图；**规模与真实节点以内容资产为准**，首版目标见 F20 的 DAG 要求。）

**四条设计规则**：

1. **节点 ID 稳定且可引用**：`kc_<slug>`（如 `kc_bayes`）。**ID 不得复用** —— 改知识点只能新增节点 + 标记旧节点 `deprecated`，否则历史作答的标注会指向错误含义。
2. **无环是硬约束**（F19 验收）：建图时做拓扑排序，有环即拒绝加载（不是警告）。加载失败必须**报错退出**，不得静默丢边。
3. **边有含义**：`depends_on`（前置）单向。上溯（F9）沿 `depends_on` 反向走。
4. **题目与题型都挂知识点**，但两者独立：一道题可以考多个知识点；一个题型可以服务多个知识点。

### 2.3 关系图

```
   内容资产（L0，入仓，可版本化）
   ┌──────────┬──────────┬──────────┬──────────┬─────────────┐
   │ 题库      │ 错因库    │ 知识点DAG │ 公式库    │ 题型与解法套路│
   └────┬─────┴────┬─────┴────┬─────┴────┬─────┴──────┬──────┘
        │          │          │          │            │
        │   kc_ids │  kc_ids  │  node    │  kc_ids    │  kc_ids
        ▼          ▼          ▼          ▼            ▼
   ┌─────────────────────────────────────────────────────────┐
   │                   知识点（KnowledgePoint）                │
   └───────────────────────────┬─────────────────────────────┘
                               │ kc_ids[]
                               ▼
   学生 ──提交──▶ 判定（确定性，不依赖 LLM） ──▶ 作答记录（Attempt）
                               │                      │
                               │ hint_used            │ kc_ids
                               ▼                      ▼
                        提示阶梯状态            掌握度（Mastery）
                               │                (user, kc) 聚合
                               ▼                      │
                       错因诊断（吃错因库）             ▼
                                             进度 / 薄弱视图（F11）
```

### 2.4 领域层的边界（这条决定了可测性）

`domain/` 是**纯函数层**：不碰数据库、不碰 FastAPI、不碰 LangGraph、不发网络请求。

| 属于 `domain` | 不属于 `domain` |
|---|---|
| 分布计算与性质推导（SymPy） | 读写 `student_attempt` |
| 判定规则与归一化（答案比对、等价性） | 调用检索 / 调用模型 |
| 知识点 DAG 的加载与拓扑排序、上溯 | 生成 SSE 事件 |
| 错因匹配（吃错因库） | 权限判断 |
| 题型的解法框架结构 | 页面渲染 |

**理由**：判定是 N1 的地基，而 N1 的验收要求"**注入 20 道已知错解必被发现**"。纯函数层可以**脱离服务、脱离数据库、脱离模型**直接跑注入集 —— 这是让 N1 的验收成本从"起服务跑端到端"降到"跑一个函数"的唯一办法。

## 3. 数据模型

### 3.1 L2 六张表（全部 `student_` 前缀，全部 per-user）

| 表 | 装什么 | 谁写 | 谁读 | 删除权（F16） |
|---|---|---|---|---|
| `student_user` | 账号（bcrypt 哈希 / 角色 / 状态 / 锁定） | `identity` | `identity` · 管理页 | **脱敏**（不可登录），不物理删 |
| `student_token` | 会话令牌（**只存 sha256**） | `identity` | `identity` | **级联删除** |
| `student_audit` | 审计：谁在何时看了 / 改了谁的数据 | `identity` | 管理页 | **保留**（已裁定，见下） |
| `student_qa_log` | 问答流水（**含提问原文**，L2 里最敏感） | `graph` 落库 | 管理页 · 统计 | 硬删 |
| `student_attempt` | 作答记录 | `learning` | 错题本 · 进度 · 管理页 | 硬删 |
| `student_mastery` | 知识点掌握度聚合 | `learning` | 进度 / 薄弱视图 | 硬删 |

> ✅ **已裁定（2026-09-16，负责人）· `student_audit` 在删除用户时保留**
> **设计**：`student_audit` **不随删除而清除**，理由：它是"管理员看过谁的数据"的合规证据，删掉它等于删掉监督记录；且账号本身是**化名**（N6 不采集学号/姓名），脱敏后 `user_id` 已无法回溯到具体的人。
> **同时要求**：删除动作本身必须写一条审计（谁删的、删了几行）。
> **已考虑并否决的替代方案**：① 删除时一并清除 `target_id` 指向该用户的行 —— 否决，因为"该生数据曾被反复查看"这件事会变得不可查，而它恰恰是监督的价值所在；② 对 `target_id` 做盐化 —— 否决，为一条本地部署的审计记录引入一个密钥管理面不划算。
> **代价（记账）**：删除后仍存在"某个匿名 ID 曾被查看过"的记录。这是**有意选择合规证据优先于彻底清除**，若日后合规要求变化，改法是上面被否决的方案 ①。

### 3.2 关键表：字段级设计

#### `student_attempt` —— 本仓的**核心表**（F7 / F19 的落点）

| 字段 | 类型 | 本仓处置 | 支撑需求 |
|---|---|---|---|
| `attempt_id` | TEXT PK | 保留 | F7 |
| `user_id` | TEXT | 保留（身份归属） | F7 · F15 |
| `student_id` | TEXT | **保留但只作历史兼容**，写入时与 `user_id` 同值；新代码不得读它 | F7（迁移期） |
| `item_id` | TEXT | 保留（指向题库条目） | F7 · F8 |
| `session_id` | TEXT | 保留（同一浏览器会话，用于「本会话用了 N 次提示」F14） | F14 |
| `kc_ids` | TEXT(JSON) | **非空强制**（见下） | **F19** |
| `correct` | INTEGER | 保留 | F7 · F11 |
| `score` | REAL | 保留（应用题部分分） | F7 |
| `answer_raw` | TEXT | 保留（学生原文） | F7 · F5 |
| `answer_normalized` | TEXT | 保留（归一化后，便于复算） | F4 |
| `expected` | TEXT | **标准答案快照**（F7 明写） | **F7** |
| `hint_used` | INTEGER | 保留（**伦理约束的落地点**，§5） | F6 · F14 |
| `duration_ms` | INTEGER | 保留 | F7 |
| `attempt_no` | INTEGER | 保留（第几次做这道题） | F8 · F11 |
| `source` | TEXT | 保留（`practice` / `wrong_review` / …） | F8 |
| `deleted` | INTEGER | 保留（软删标记，供管理页撤回误删） | F16 |
| **`asset_version`** | TEXT | ★ **新增字段** | **F7** |

**新增 `asset_version` 的理由与合规性**：
F7 要求"**标准答案快照 + 资产版本号**"。`expected` 已提供快照，但快照离了版本号**无法解释**——题库改版后，"当时的标准答案"为什么是这个值、知识点标注依据的是哪一版 DAG，都查不出来。
**这是"只增不改"允许的增量变更**：新字段可空、有默认值、不改变任何既有字段的含义，旧数据读出来是 NULL 而非错误。

**`kc_ids` 非空的实现路径（F19）**：
不是"在写入时校验一下"这么弱 —— 而是**从源头保证**：F20 要求**题库条目必须关联知识点 ID**，而 `attempt.kc_ids` 由题目继承。因此：

```
题库条目 kc_ids 必填（F20）
        └─▶ 作答时继承 kc_ids
                └─▶ attempt.kc_ids 天然非空（F19）
```

三层都要有断言：① 题库加载时校验条目 `kc_ids` 非空；② 契约里 `kc_ids` 标 `minItems: 1`；③ 写入函数拒绝空数组并抛错（**不得静默写 `[]`**）。
> 为什么强调第三层：旧仓该列是 `NOT NULL DEFAULT '[]'` —— **"非空"在数据库层面看起来被满足了，实际存的是空数组**。这正是 F19 要防的那种"表面合规"。

#### `student_mastery` —— 聚合口径

| 字段 | 说明 |
|---|---|
| `user_id` + `topic`（PK） | `topic` **就是知识点 ID**（与 `attempt.kc_ids` 同口径，不再另设一套命名） |
| `attempts` / `correct` | 聚合计数 |
| `updated_at` | 最后更新时刻 |

**更新时机**：**每次作答后累加**（同事务）。**不做**"重算全表"——重算会在删除 / 软删时产生漂移。
**已知限制（诚实）**：当前口径是**计数**，不含"提示次数对掌握度的扣减"。F6 要求如实记录，但**掌握度公式本身不在 v2 范围内**（属学习者建模，§9 不做）。数据齐备，公式后补 —— 这正是"现在开始记"的意义。

#### 其余四张表
`student_user` / `student_token` / `student_qa_log` 的字段沿用已落地实现（逐字搬运，逻辑零改动）；`student_audit` 同理。**字段级机器可读定义在 `contracts/`（A3）**，本篇只记录**本仓的增量**（即 `asset_version`）与口径说明。

### 3.3 内容资产：五类、格式与版本化（F20）

| 资产 | 最小规模（首版） | 必须关联 | 主要消费方 |
|---|---|---|---|
| 题库 | 与评测资产共用（C1 ≥ 100 道为长期目标） | 知识点 ID · 题型 ID | 刷题 · 评测 |
| 错因库 | **≥ 40 条** | 知识点 ID | F5 错因诊断 |
| 知识点 DAG | 拓扑无环 | —（节点即 ID） | F9 · F19 · 上溯 |
| 公式库 | — | 知识点 ID | F18 精准检索 |
| 题型与解法套路 | **≥ 15 类** | 知识点 ID | **F17 的"适用模型"** |

**统一版本化规则**：

1. 每类资产一个文件（或一个目录 + 索引），**文件头带 `rev`**：`<asset>-<YYYY.MM.DD>.<n>`。
2. 生成物 `backend/data/content/MANIFEST.json` 记录**五类资产各自的 rev**，并派生出**组合版本号** `content_rev`（五者 rev 的确定性拼接）。
3. `attempt.asset_version` 存**当时的 `content_rev`**；要查细节就按 MANIFEST 反解到具体资产 rev。
4. **`rev` 变更即视为内容变更**：改一个错因解释也要升 `rev`。**不允许原地改内容不升版本** —— 否则历史记录的解释链断裂。

> 资产**入仓**（L0，自制、可版本化、可 diff、可 review）；**教材语料不入仓**（L1，见 §1.3）。
> 这与 N3 不冲突：入仓的是我们自编的题目、错因、DAG、公式、题型；从教材摘录的原文属 L1。

| `user.password_hash` | **N6**（只存哈希） | — |
| `user.status` · `failed_count` · `locked_until` | **F15**（禁用 / 锁定） | — |
| `token.token_hash` | N6（只存 sha256） | — |
| `audit.*` | **F15**（管理员看数据的留痕） | — |

**这张表里没有"说不出用途的字段"**，也没有一个字段是为"页面要显示什么"而加的 —— 附录 A 的规则在第一次执行时就是干净的，因为数据模型是从需求推出来的，不是从界面反推的。

**规则 2：每条 MUST 需求至少被一个字段或一个接口支撑 —— 说不出的补上。**
逐条核对见 **§10**（不是全部 MUST 都需要新字段：有的靠接口、有的靠规则，但**每一条都必须能指出落点**）。

### 3.5 索引与查询

| 索引 | 服务的查询 |
|---|---|
| `user(role, status)` | 管理页按角色 / 状态筛选 |
| `token(user_id, revoked)` | 撤销某用户全部令牌 |
| `audit(actor_id, created_at)` · `audit(target_id, created_at)` | 审计按人 / 按被查看者 |
| `qa_log(user_id, created_at)` | 我的问答历史（**cursor 分页的主键序**） |
| `attempt(user_id, created_at)` | 错题本 / 进度（**cursor 分页**） |
| `attempt(user_id, item_id)` | 同一题的第几次（`attempt_no`） |
| `mastery(user_id, topic)`（PK） | 薄弱点定位 |

### 3.6 并发与事务（R-B 的落地）

| 规则 | 做法 | 为什么 |
|---|---|---|
| 并发写 | 开启 **WAL** + `busy_timeout=5000` | 读写不互相阻塞；短时争用自动重试而非立即报错 |
| 建表 | **只有一个建表入口**，幂等 | 分两处建表必出"某个入口漏建了表"，症状是运行时的 `no such table` |
| 写事务 | 每次写**显式 `commit()`**，并集中在一个 `with closing(conn)` 里 | 旧仓真实 bug：写函数漏一次提交，作答记录被**静默回滚** |
| 复合写 | `作答 + 掌握度 + 问答流水` 的联动写在**同一事务**内 | 否则会出现"记了作答但掌握度没动"的半成品状态 |
| 测试 | **必须读回断言**，不得只断言"HTTP 200" | 同上的 bug 当时没被发现，就是因为测试只看了状态码 |

## 4. 三条主链路

### 4.1 登录与令牌链路（F15 · N6）

```
浏览器                        后端                         SQLite(L2)
  │                            │                              │
  │ POST /api/auth/login       │                              │
  │ {username, password}       │                              │
  ├───────────────────────────▶│                              │
  │                            │ ① 查 user（含 locked_until） │
  │                            ├─────────────────────────────▶│
  │                            │ ② 锁定中？→ 423              │
  │                            │ ③ status=disabled？→ 403     │
  │                            │ ④ bcrypt.checkpw             │
  │                            │    失败 → failed_count+1     │
  │                            │    达上限 → 置 locked_until  │
  │                            │    且**校验失败也烧时间**     │
  │                            │ ⑤ secrets.token_urlsafe(32)  │
  │                            │    库里只存 sha256(明文)      │
  │                            ├─────────────────────────────▶│
  │ {token, expires_at, user}  │◀─────────────────────────────┤
  │◀───────────────────────────┤                              │
  │                            │                              │
  │ 后续请求：Authorization: Bearer <token>                    │
  ├───────────────────────────▶│ resolve_token(sha256)        │
  │                            │ → revoked/过期/账号禁用 ⇒ 401/403
```

**七条口径（每条都对应一个具体的坏结果）**：

| # | 口径 | 不做会怎样 |
|---|---|---|
| 1 | **服务端会话令牌，不是 JWT** | JWT 无状态 → 无法满足"停用账号**立刻**生效" |
| 2 | 库里**只存 sha256**，明文只在登录响应出现一次 | 库被拿走等于所有会话被劫持 |
| 3 | 令牌 **7 天**有效，可即时撤销（`revoked`） | 无法响应"这孩子手机丢了" |
| 4 | **改密码 / 禁用 / 删除 ⇒ 撤销该用户全部令牌** | 改完密码旧令牌还能用，等于没改 |
| 5 | 失败 **5 次锁 60 秒**；**校验失败也烧固定时间** | ① 可无限爆破 ② 通过响应时间可枚举用户名是否存在 |
| 6 | 除 `health` / `login` / 静态资源外，**全部端点要求登录** | **A1 已裁决：不设免登录例外**（理由见 `docs/01` §1） |
| 7 | 管理员账号**只能由 CLI 创建**，接口不可创建管理员 | 否则拿到一个管理员令牌就能自我复制 |

### 4.2 答疑链路（SSE · F1 F2 F3 F10 F13）

```
POST /api/chat  { query, context }        ← 必须登录（F15）
   │
   ├─ ① 校验：query 长度上界（R-A）· context 可缺省但显式降级（F1）
   ├─ ② 落 qa_log（提问原文，L2）—— 先落再答，保证"问了就算数"
   │
   ▼  graph（LangGraph 图运行时）
   ├─ 路由 → 意图（solve / explain / lookup / visualize）
   ├─ 检索（本地语料）→ 命中带出处；**无命中如实说明**（F10 · N2）
   ├─ 求解 → 逐步过程，每步 {说明, 式子}（F2 结构断言）
   ├─ 验证 → **验证报告**（级别 A–D + 逐项检查 + 置信度）—— 每条解答必带（F3）
   ├─ 需要人协同？→ hitl.request（挂起，等前端确认）
   └─ 汇总 → 事件流
   │
   ▼ SSE 帧（`events.schema.json`）
   │   frame: { seq, type, ts, payload }   seq 单调递增
   ▼
前端消费：seq 去重 · 按类型渲染 · 断流可续 · 不重放已渲染帧
```

**五条硬性设计**：

1. **事件序号 `seq` 单调递增** —— 前端据此去重与断流续传；没有它，重连就会重复渲染。
2. **客户端断开 ⇒ 图必须取消**。否则一次刷新页面会留下一个还在跑的后台图，把单 worker 拖死。
3. **验证报告缺失即不出结果**（F3："无标签不出结果"）—— 这是 N2 的机制，不是前端的事。
4. **`hitl.request` / `hitl.resolved` 必须成对**，且前端必须有可见的挂起态 —— 否则用户面对一个永远不动的进度条。
5. **上下文来源可替换**（N12）：`context` 是一个**显式可选参数**，不是"从浏览器读屏"。将来探针接入时，它只是换一个来源，**契约不变**。

### 4.3 刷题判分链路（F4 F5 F6 F7 F8 · N1）

```
GET  /api/problems?kc=...&limit=&cursor=      ← 题目来自内容资产（F20）
POST /api/practice/grade
     { item_id, answer, hint_used, duration_ms, session_id, attempt_no }
   │
   ├─ ① 参数校验：answer **max_length=200**（R-A）· 数值上界
   ├─ ② 归一化（domain 纯函数）：去空白 / 统一符号 / 精度口径
   ├─ ③ 判定（domain 纯函数，**不依赖 LLM 往返**，F4）
   │      ├─ 正确 → correct=1
   │      └─ 错误 → 错因匹配（吃错因库，F5）
   │            命中 → 输出对应错因解释
   │            未命中 → **如实说"未识别错因"**，不得编造
   ├─ ④ 定级：本判定为**确定性**，验证级别按手段封顶（附录 C）
   │
   ├─ ⑤ **同一事务**写入：
   │      attempt（含 expected 快照 + asset_version）  ← F7
   │      mastery（(user_id, topic) 累加）              ← F11
   │      显式 commit()                                 ← R-B
   ▼
GET  /api/me/wrong?kc=...&limit=&cursor=      ← 跨会话读回（F8）
GET  /api/me/progress                          ← 进度 / 薄弱（F11，数据源=attempt）
```

**四条硬性设计**：

| # | 设计 | 对应 |
|---|---|---|
| 1 | 判定**全部走确定性代码**，且是**同步 CPU 工作 ⇒ 必须丢线程池** | F4 · **旧仓 P0 事故**：`/api/practice/grade` 曾冻结整个事件循环 |
| 2 | 判定正则**禁止嵌套量词**；对长数字串有专门测试 | R-A · 旧仓实测：100k 位数字耗时约 2 分钟 |
| 3 | 提示分级由**独立接口**推进，每次 +1 写 `hint_used`；**未提交前不返回完整解析** | F6 · §5 伦理约束 |
| 4 | 判定接口**只读题目、不写题库**；内容资产是只读的 | F20（资产一致性） |

## 5. 状态机

### 5.1 编排图状态机

```
idle ──▶ routing ──▶ running ──┬──▶ verifying ──┬──▶ done
                      ▲         │                │
                      │         │                └──▶ needs_human ──▶ hitl
                      │         │                                    │
                      └─────────┴──◀──────── resolved ◀──────────────┘
                                │
                                └──▶ failed（错误体见 §6.2）
```

**约束**：`done` / `failed` 为终态；`needs_human` **必须有超时**（否则图永远挂着）。
**已知限制（诚实）**：图检查点当前为**内存态** ⇒ **只允许单 worker**。见 §8 的失败模式表。

### 5.2 提示阶梯状态机（F6 —— 伦理约束的落地点）

```
        未作答
          │ 请求提示 1
          ▼
    hint_used=1 ──「方向」**不给完整思路**
          │ 请求提示 2
          ▼
    hint_used=2 ──「步骤骨架」**不给最终答案**
          │ 提交作答
          ▼
        已提交 ──▶ 此时才允许返回**完整解析**
          │ 错题重做（source=wrong_review）
          ▼
        重新作答（attempt_no+1，hint_used **重新计**）
```

**三条不可违反**：① 未提交前**不返回完整解析**；② 每次提示**精确 +1**（这是"如实记入掌握度"的依据）；③ 重做时 `hint_used` 重新计，但**历史不清零**（否则"我第三次才做对"的证据就没了）。

### 5.3 账号状态机（F15）

```
          创建(CLI)              禁用(管理员)
   (无) ──────────▶ active ◀───────────────▶ disabled
                     │  ▲                        │
        删除(本人/管理员) │  │ 启用(管理员)          │
                     ▼  │                        │
                  deleted ◀───────────────────────┘

   任一状态下的失败计数：failed_count≥5 ⇒ locked_until 置未来时刻（60s 后自动解除）
```

**`deleted` 是脱敏态，不是物理删除**：`username` 改为 `deleted_<8hex>`、`password_hash` 置空串（**任何密码都登不进去**）、令牌全撤；三张学习表的数据**硬删**。

### 5.4 令牌状态机

```
issued ──▶ active ──┬──▶ expired（到期）
                    ├──▶ revoked（改密 / 禁用 / 删除 / 主动登出）
                    └──▶ orphan（账号被删除后，行被级联清理）
```

## 6. 接口与错误语义

### 6.1 路由清单（按模块）

| 模块 | 端点 | 认证 | 备注 |
|---|---|---|---|
| 系统 | `GET /api/health` | **否** | 唯一无需登录的 API；报告 DB / 模型 / 检索状态 |
| 身份 | `POST /api/auth/login` | 否 | 唯一另一个例外 |
| 身份 | `POST /api/auth/logout` · `POST /api/auth/password` | 是 | 改密后撤销全部令牌 |
| 身份 | `GET /api/me` · `GET /api/me/wrong` · `GET /api/me/progress` · `DELETE /api/me/data` | 是 | **学生只见自己**（F15） |
| 答疑 | `POST /api/chat`（SSE） · `GET /api/runs/{id}` | 是 | 事件 `seq` 单调 |
| 刷题 | `GET /api/problems` · `POST /api/practice/grade` | 是 | 判定确定性 + 线程池 |
| 知识 | `GET /api/knowledge/tree` · `GET /api/knowledge/formula` | 是 | 吃 DAG / 公式库（F18） |
| 管理 | `GET /api/admin/students` · `GET /api/admin/users` · `GET /api/admin/audit` · `PATCH/DELETE /api/admin/users/{id}` · `POST /api/admin/users/import` | 是（**管理员**） | 一律写审计 |

**R-A 强制的字段**（所有请求体字符串字段必须有上界）：

| 字段 | 上界 | 理由 |
|---|---|---|
| `username` | 32 | 契约正则 `^[A-Za-z0-9_.-]{3,32}$` |
| `password` | 72 字节 | bcrypt 输入上限 |
| `answer` | **200** | 旧仓 P0：无上界 ⇒ 判定被喂 100k 位数字 |
| `query` | **2000** | 答疑提问；超长直接 400 |
| `display_name` | 64 | — |

### 6.2 统一错误体（`error.schema.json` —— 旧仓的缺口之一）

```json
{
  "error": {
    "code": "unauthenticated",
    "message": "未登录或登录已过期，请重新登录",
    "detail": { "field": "password", "reason": "too_short" }
  }
}
```

| 字段 | 含义 | 约束 |
|---|---|---|
| `code` | **机器读的稳定标识**（枚举，见 §6.3） | 只增不改；新增须走契约变更 |
| `message` | **给人看的中文说明** | 不含内部路径 / SQL / 堆栈 |
| `detail` | **可选**结构化补充（哪个字段错了、缺什么） | 不得放敏感值 |

**为什么要有它**：旧仓每个接口各写各的形状（有时是字符串，有时是对象，有时干脆是 500），前端只能按形状猜。**统一错误体是前端能写出一套错误处理的前提**。

### 6.3 状态码与 `code` 语义表

| HTTP | `code` | 触发条件 | 前端行为 |
|---|---|---|---|
| 400 | `invalid_argument` | 参数校验失败（含超长、格式） | 高亮字段 + 显示 `message` |
| 401 | `unauthenticated` | 无令牌 / 令牌无效 / 已过期 / 已撤销 | **清本地令牌 + 跳登录** |
| 401 | `bad_credentials` | 登录时用户名或密码不正确 | 显示提示，**不清空用户名** |
| 403 | `forbidden` | 越权：读他人数据 / 非管理员访问管理接口 | 显示"无权访问"，**不跳登录** |
| 403 | `account_disabled` | 账号被禁用 | 显示"账号已停用，请联系老师" |
| 404 | `not_found` | 资源不存在（含"不属于我"的资源，**故意不区分**） | 友好提示 |
| 409 | `conflict` | 用户名已存在 | 提示换一个 |
| 423 | `locked` | 连续失败过多，短时锁定 | 显示剩余秒数 |
| 500 | `internal_error` | 未预期错误 | 显示"服务出错"，**附 trace id** |
| 503 | `dependency_unavailable` | 模型 / 检索不可用且无降级路径 | 提示"当前为降级模式" |

> **两条刻意设计**：① **越权返回 404 而非 403**（"别人的资源"对外看起来"不存在"），避免通过状态码探测他人 ID 是否存在；**但日志里记 403**，便于排查。② `account_disabled` 用 **403** 与 `forbidden` 区分 —— 用户需要知道"是账号问题"而不是"权限问题"。
> ✅ **已裁定（2026-09-16，负责人）**：旧仓把"账号被禁用"与"权限不足"都归 403 且用同一段文案；**本仓分成两个 `code`**（`account_disabled` / `forbidden`），理由是用户需要知道"这是账号问题，去找老师启用"而不是"我权限不够"。
> **已考虑并否决的替代方案**：退回单一 `forbidden`（理由是避免泄露"该账号存在且被停用"）。否决依据：**能走到 403 说明对方已通过密码验证**（登录接口对不存在的用户与密码错误返回同一个 `bad_credentials`），因此 `account_disabled` 不构成额外的枚举面。

### 6.4 分页口径（旧仓的第二个缺口）

**统一为 cursor 分页**，不用 `offset`：

```
请求：?limit=20&cursor=<opaque>
响应：{ "items": [...], "next_cursor": "<opaque>|null" }
```

| 规则 | 值 |
|---|---|
| `limit` 默认 / 上界 | 20 / **100**（超界即 400，不静默截断） |
| `cursor` | 不透明字符串（内部是 `created_at` + `id` 的编码），**客户端不得解析** |
| 排序 | 一律 `created_at DESC, id DESC`（稳定序，避免同秒记录乱序） |

**为什么不用 offset**：问答流水与作答记录是**追加写**的表，翻页时新记录插入会让 offset 漂移 ⇒ **同一条记录被读到两次、或某条被整页跳过**。这对"错题本复习"是真实伤害。

### 6.5 SSE 帧

帧格式与 14 类事件由 `events.schema.json` 定义（A3）。本仓对**帧的两条增量要求**：

1. **每帧带 `seq`（单调递增整数）** —— 断流续传与去重的唯一依据。
2. **终帧必须显式**（`done` 或 `error`）—— 让前端能区分"跑完了"与"网断了"，否则只能靠超时猜。

## 7. 前端系统设计

### 7.1 URL 可寻址设计（N11 —— 旧仓实测返回键失效）

**规则**：**凡是有意义的界面状态，必须由 URL 表达**。顺序是"URL 是状态源，组件是它的投影"，不是反过来。

| 路由 | 表达的状态 | 为什么必须可寻址 |
|---|---|---|
| `#/login` | 登录页 | — |
| `#/home` | 首页 | — |
| `#/practice?kc=kc_bayes&item=prob_0012&hint=2` | **具体题目的具体提示层级** | "刷到第 3 步提示"要能刷新、能分享、能回退 |
| `#/wrong?kc=kc_bayes&cursor=<opaque>` | 错题本 + 知识点筛选 + 翻页位置 | 复习到一半刷新不能回到起点 |
| `#/knowledge?kc=kc_bayes&view=graph` | 知识点定位 + 视图模式 | 分享"就是这个知识点不会" |
| `#/admin?tab=students&user=usr_xxx` | 管理页标签 + 选中学生 | 管理员排查时要能把链接发给别人 |

**两条实现要求**：① 监听 `hashchange` **与** `popstate`（旧仓只写 hash、无人监听 ⇒ 返回键只变 URL 不变视图）；② 视图状态从 URL **单向派生**，组件不得各存一份。

### 7.2 外壳与页面注册

| 部分 | 职责 | 谁写 |
|---|---|---|
| `frontend/index.html` | 唯一 HTML；引 CSS（4 层）与 `bootstrap.js` | R1 |
| `core/` | `dom`（创建元素 / 转义）· `bus`（事件）· `store`（内存态）· `router`（**含 hashchange**）· `api`（fetch 包装 + 错误体解析）· `auth`（令牌 / 角色） | R1 |
| `components/` | 复用 UI（表格 / 卡片 / 骨架 / 空态 / 图表） | R1 |
| `features/<x>/` | `feature.json`（id / route / 标题 / 顺序）+ `index.js` + `styles.css` | **一人一页** |

**依赖方向**：`features/*` **不得互相 import**（只能经 `core/bus.js`）；`components` 不得 import `features`。

### 7.3 样式分层（**单一令牌源**）

```
styles/tokens.css       ← ★ 唯一变量源（颜色/圆角/阴影/间距/过渡）
styles/app.css          ← 外壳骨架（布局、侧栏、顶栏）
styles/components.css   ← 通用组件
styles/pages.css        ← 页面模板层（页面头/工具栏/表格/空态/骨架）
features/<x>/styles.css ← 只写该页独有样式，**禁止硬编码颜色**
```

**规则**：任何颜色 / 圆角 / 阴影**只能来自 `tokens.css`**。旧仓 `widget.css` 有 **77 处硬编码色值**（其中 13 处与 token 同值）—— 那是双形态遗留；v2 单形态下这条规则可被脚本扫描守住。

### 7.4 状态管理的边界

| 状态 | 存哪 | 为什么 |
|---|---|---|
| 令牌 | `localStorage` | 免构建、无后端渲染；XSS 风险由"不用 `innerHTML` 拼用户内容"控制 |
| 界面位置（知识点 / 题目 / 提示层级 / 翻页） | **URL** | N11：可刷新、可分享、可回退 |
| 跨页面临时态（当前 run、未提交的作答） | `core/store`（内存） | 刷新即丢是**可接受的** —— 它们本来就不该是持久状态 |
| 持久学习数据 | **只在服务端** | 单一真相；避免前后端两套数据打架 |

## 8. 失败模式与降级（一开仓就定死，不留给日后踩）

| # | 场景 | 设计行为 | 谁守（测试） |
|---|---|---|---|
| 1 | **未登录 / 令牌过期** | 401 `unauthenticated`；前端清令牌并跳登录 | 接口测试 |
| 2 | **令牌被撤销**（改密 / 禁用 / 删除） | 立即 401（**不是等 7 天**） | 接口测试 |
| 3 | **越权读他人数据** | 404（对外）· 403（日志） | 越权用例 |
| 4 | **账号禁用 / 锁定** | 403 `account_disabled` / 423 `locked` | 接口测试 |
| 5 | **超长输入** | 400（有上界）；**绝不进入判定** | R-A 扫描 + 长度用例 |
| 6 | **正则灾难性回溯** | 禁嵌套量词；数字长串专项用例 | 用例（100k 数字须 < 1s） |
| 7 | **判定阻塞事件循环** | 同步 CPU 工作全部 `to_thread` | 并发健康检查（**判定压测时 `/api/health` 必须仍 < 100ms**） |
| 8 | **写库静默回滚** | 显式 `commit()`；测试读回断言 | R-B 扫描 + 读回用例 |
| 9 | **SQLite 并发写** | WAL + `busy_timeout=5000` | 并发写用例 |
| 10 | **SSE 客户端断开** | **取消图**，释放资源 | 断流用例（断开后无残留任务） |
| 11 | **SSE 网络中断** | 前端按 `seq` 续传 / 重连；不重复渲染 | 前端用例（注入重连） |
| 12 | **图挂起无人应答（HITL）** | 挂起**必须有超时**，超时后按降级路径收尾 | 超时用例 |
| 13 | **模型 / 检索不可用** | 降级为本地确定性路径；**界面显式说明降级**（N2） | 无 KEY / 断网冒烟 |
| 14 | **内容资产加载失败（DAG 有环 / 条目缺 kc_ids）** | **启动即报错退出**，不得静默丢边或写空标注 | 资产校验脚本 |
| 15 | **单 worker 约束被违反** | 启动时检测并发度；>1 即**拒绝启动并说明原因** | 启动用例 |
| 16 | **删除用户后仍能登入** | 不可登录（空哈希）；令牌已撤 | 接口测试 |

> **第 14 条为什么必须"报错退出"而不是"警告后继续"**：F19 要求 DAG 无环、F20 要求条目挂知识点。资产坏了而系统照跑，产生的是**带错误知识点标注的作答记录** —— 那些记录会污染掌握度与错题本，且事后无法区分哪些是坏的。**宁可起不来。**
> **第 15 条为什么必须是启动检测**：旧仓把"只允许单 worker"写在文档里，**代码不检测** —— 于是部署时多开一个 worker 就出现"随机丢 run / 事件串台"，而症状看起来像前端 bug。

### 11.2 诚实缺口（本篇现在缺什么）

1. **题库与题型的真实规模未定**：F20 只给了错因库 ≥ 40 条、题型 ≥ 15 类；**题库首版多少道没有数字**——因为它同时是评测资产（≥100 道为长期目标）与内容资产，两个口径尚未对齐。
2. **`student_user` 的字段级定义不在本篇**：沿用已落地实现（逐字搬运），机器可读定义在 A3 的契约里。本篇只记增量（`asset_version`）。
3. **掌握度公式不在 v2 范围内**（属学习者建模，§9 不做）：因此 `mastery` 目前只是计数，**F11 的"薄弱"判定阈值尚未定义**——数据齐备，算法后补。
4. **HITL 的超时长度未取值**：需要一个经验值，且它决定用户等多久才看到降级结果。建议在阶段 C 用真实链路测完再定。
5. **`content_rev` 的组合算法未定**：本篇只定"五类 rev 的确定性拼接"，具体拼接与哈希形式在 A3 随 `MANIFEST.json` 一起定。
6. **缓存已热（§6 测量条件）没有可操作定义**："首次请求后 warmup"听起来明确，但**warmup 几次算热**没有标准 —— 若不定，性能验收会有争议。
7. **前端 XSS 防线只有一条**（不用 `innerHTML` 拼用户内容）：没有 CSP、没有 DOMPurify。免构建 + 离线的前提让它不好引库，但**这条防线是纪律，不是机制**——已在 §7.4 记账。

**以上 7 条都不阻塞 A2 定稿**，但第 1、4、6 条必须在写 `docs/06`（阶段门）之前定，否则验收动作会含糊。
