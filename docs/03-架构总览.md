## 1. 一句话架构与五条设计原则

**一个单进程的 FastAPI + 单 worker 图运行时，中间是单向依赖的分层；前端是免构建的原生 ESM 单页；契约是前后端之外的第三方。**

```
浏览器（原生 ESM · 零 npm · vendor 本地化）
   │  HTTP + SSE（★ POST + fetch 流，见 docs/02 §4.2.1）
   ▼
api/          路由层：必须薄 —— 校验 / 鉴权 / 序列化，不含业务
   ▼
graph/        LangGraph 编排：节点只做「取输入 → 调 domain|tools → 落事件」
   ▼
domain/       纯函数领域层：判定 · 归一化 · 错因匹配 · 分布 · DAG（无 IO / 无框架 / 无网络）
   ▼
core/         基础设施：配置 · 统一错误体 · 日志

   identity/   账号与令牌（从旧仓 tools/ 提出来）
   learning/   学习留痕：问答流水 · 提示流水 · 作答 · 掌握度
   tools/      检索 / ★ llm.py（唯一运行期出网口）
```

**五条设计原则 —— 每条必须带来源，因为"原则"是最容易变成口号的东西**：

| # | 原则 | 一句话 | 来源 |
|---|---|---|---|
| 一 | **契约优先** | 前后端各自实现的形状由 `contracts/` 定死；**契约不属于任何一端** | `ADR-0003` 决策 7 · `docs/01` 承诺 12 |
| 二 | **显式优于隐式** | 注册、允许集合、错误码都要能 **grep** —— 不靠扫描目录"自动发现" | §7① 的裁定（2026-09-16）· **R-Q** |
| 三 | **能算的不要问模型** | 判定走确定性代码，**判定链路中无 LLM 调用** | `docs/01` F4 · `docs/02` §4.3-1 |
| 四 | **唯一出网口** | 运行期只有 `tools/llm.py` 联网 | `ADR-0005` §3 · **R-K** |
| 五 | **纯函数领域层** | `domain/` 脱离服务、数据库、模型即可单测 | §4 · `docs/01` N1 |

> ★ **旧仓的「原则五：离线可用」不收录（2026-09-16）** —— 它的理由是 `ADR-0001` 的"离线 / 内网演示"，而该前提已被 **`ADR-0004` 证伪**：N3 废弃、N4 收窄为"免安装"，完整链路依赖网络与用户凭据。
> **为什么必须把这条明确写出来**：本轮评审查出的两处漂移（`docs/02 §1.2` 与 §1.6 的 R-E）**都还在用"离线"当理由**。一条已经作废的原则留在表里，下一轮一定还会有人拿它当依据。详见 §10。

## 2. 目录骨架（★ 唯一权威）

**本节是目录骨架的唯一权威。** `ADR-0003` 决策 4 给的是建仓时的骨架，已被三处细化（`ADR-0003` §v2 增量第 8 行）；**冲突时以本节为准**（ADR 是历史记录）。

```
contracts/                       契约层（不属于前后端，属于项目）
content/                         ★ L0 自制内容资产（顶层，与 contracts/ 并列）
  MANIFEST.json                  五类资产各自的 rev + 组合版本号 content_rev（★ 入仓）
  <asset>.json                   题库 / 错因库 / 知识点 DAG / 公式库 / 题型与解法套路
  eval/sample/                   N13 的样例集（入仓、进门禁）

backend/app/
  core/                          基础设施：配置 / 统一错误体 / 日志
  identity/                      ★ 账号体系：存储层 + 鉴权内核 + 3 个 API 模块（搬运件）
  domain/                        纯领域（§4）
  learning/                      学习留痕：问答流水 / 提示流水 / 作答 / 掌握度
  api/                           路由层，必须薄（§3.2）
  graph/                         LangGraph 编排 + 节点注册表（§7①）
  tools/                         工具：retrieval / ★ llm.py（唯一出网口）

backend/data/                    ★ 纯运行时目录 —— .gitignore 整目录 deny-by-default
  corpus/<教材>/ch<nn>/sec<nn>.md   L1 开放许可资源缓存（预抓产物，不入仓）
  logs/                          ★ 日志（R-O：只记 ID 与动作），轮转 10MB × 5
  backups/                       ★ N19 备份产物（同机另一个卷 / 目录，不含日志）
  *.sqlite                       L2 学生库（七张 student_ 表）

backend/tests/
frontend/
  index.html                     唯一 HTML
  core/                          dom / bus / store / router（含 hashchange）/ api / auth
  components/                    复用 UI（表格 / 卡片 / 骨架 / 空态 / 图表）
  features/<x>/                  feature.json + index.js + styles.css（一人一页）
  styles/                        tokens.css / app.css / components.css / pages.css
  vendor/katex/                  ★ 本地化（零依赖；理由见 ADR-0001 的 §v2 重新评估）
  assets/animations/             F12（MAY · 未排期 · 见 §9.3）

docs/   scripts/
```

**三条随骨架一起生效的规则**：

1. ★ **`backend/data/` 整目录 deny-by-default**，而不是"精确匹配库文件后缀" —— 旧写法的洞是 glob 的 `*`**不跨目录**（`backend/data/*.sqlite` 匹配不到子目录里的库）。**"结构上不可能入仓"这句话靠的就是这条规则本身**（`docs/02 §1.3`）。
2. ★ **表名是数据分级口径，目录是代码归属口径** —— 两者严格分开。因此把存储层拆到 `identity/` 与 `learning/` **不会**破坏"一条 `LIKE 'student_%'` 排除全部敏感表"这条安全属性（`ADR-0003` 决策 5）。
3. **本节列出的目录才算存在的东西** —— 旧仓的 `kernel/` · `agents/` · `providers/` · `frontend/shared/` · `frontend/widget/` · `backend/knowledge_base/` · `backend/data/question_bank/` **在 v2 都不存在**，理由逐条见 §10。

## 3. 依赖方向（强制表 · 每条都有检查方式）

`ADR-0003` 决策 4 的原话是「**依赖方向由脚本检查，不靠自觉**」。本节把这句话落成一张表：**执行者是门禁，不是人**。

### 3.1 模块依赖表

| 模块 | 允许依赖 | 明确禁止 | 检查方式 |
|---|---|---|---|
| `domain/` | `core/` | 数据库 · FastAPI · LangGraph · 网络 · `tools/` · `learning/` | **可自动**：静态扫描 import 白名单 |
| `tools/` | `core/` · `domain/` | `api/` · `graph/` | **可自动** |
| `learning/` | `core/` · `domain/` | `api/` · `graph/` | **可自动** |
| `identity/` | `core/` | `api/` · `graph/` · `domain/`（身份不需要判定） | **可自动** |
| `graph/` | `core/` · `domain/` · `tools/` · `learning/` · `identity/` | `api/` | **可自动** |
| `api/` | 全部下层 | **反向被下层 import**（下层不得 import `api/`） | **可自动** |
| 前端 `features/*` | `core/` · `components/` | **互相 import** · 后端 Python 模块 | **可自动**（grep import） |
| 前端 `components/` | `core/` | `features/` | **可自动** |
| 前端全部 | 本地 `vendor/` | **任何外部 CDN / npm 包** | **可自动**（grep 外部 `<script src>` / `import` 的 http 地址；与 **N18 验收②**同一条断言） |

> ★ **`domain` 只依赖 `core` 这一条是整张表的地基**，理由见 §4：它让 N1 的验收成本从"起服务跑端到端"降到"跑一个函数"。其余各条都是它的推论。

### 3.2 三条结构性纪律（不是"风格"，是能被脚本或用例抓住的形状）

| # | 纪律 | 为什么 | 检查方式 |
|---|---|---|---|
| 1 | **`api/` 必须薄**：单路由函数 **≤ 40 行**、不含业务分支、**不写 SQL** | `ADR-0003` 决策 4 的原话是"`api` 必须薄"—— 而"薄"是形容词，**形容词无法进门禁**。★ 40 行是 **2026-09-16 的首次取值**（宁可先定一个能被脚本断言的数，也不要一个谁都能解释的形容词），调整须走 ADR | **可自动**：按函数统计行数 + grep SQL 关键字 |
| 2 | ★ **业务逻辑不得写进图节点函数** | `ADR-0003` 决策 4 与 `docs/02 §1.2` 两处点名。节点若自己算判定/错因，就会出现"**同一套规则在图里和 `domain` 里各有一份**" —— 而 N1 的注入集**只测 `domain`** | **可自动**（启发式）：扫 `graph/nodes/*` 是否 import `domain` 之外的计算库（sympy 等）；**并 review** |
| 3 | ★ **同步 CPU 工作一律 `to_thread`**（判定链 **与** 答疑链） | `docs/02 §4.2-8`：答疑链此前没有这条，而 N20 承诺的是 **10 路并发答疑**；占住事件循环会让 10 路退化成串行，`/api/health` 的 `§8-7` 断言会当场失败 | **可自动**：**R-M ①–⑦**（凭据七面不落 + 假 provider 抓载荷，施加点见 `docs/02 §1.6`）+ **N20 的压测与断流用例**；本条的"同步重计算"本身只有启发式检查（见 §9.3-4），**它不是 R-M 的替代品** |

> ★ **第 1 条的数字是唯一一处"我定的阀值"** —— 它写在正文而不是藏在脚本里，就是为了让它可以被推翻。

## 4. 领域层的边界

> ★ **本节 2026-09-16 自 `docs/02 §2.4` 移入**（一主题一篇：**分层与依赖是 `docs/03` 的主题**）。`docs/02 §2.4` 现只留一行指针。

`domain/` 是**纯函数层**：不碰数据库、不碰 FastAPI、不碰 LangGraph、不发网络请求。

| 属于 `domain` | 不属于 `domain` |
|---|---|
| 分布计算与性质推导（SymPy） | 读写 `student_attempt` |
| 判定规则与归一化（答案比对、等价性） | 调用检索 / 调用模型 |
| 知识点 DAG 的加载与拓扑排序、上溯 | 生成 SSE 事件 |
| 错因匹配（吃错因库） | 权限判断 |
| 题型的解法框架结构 | 页面渲染 |

**理由**：判定是 N1 的地基，而 N1 的验收要求"**注入 20 道已知系统错解必被发现**"。纯函数层可以**脱离服务、脱离数据库、脱离模型**直接跑注入集 —— 这是让 N1 的验收成本从"起服务跑端到端"降到"跑一个函数"的**唯一**办法。

**三条推论（都在别处已经生效，这里点明它们的共同前提）**：

1. `docs/02 §4.3` 的判定链路（归一化 → 判定 → 错因匹配）**全部落在 `domain`**，路由只做参数校验与落库；
2. `docs/02 §9.1` 的**答案级注入集**能走"错因匹配的**函数级入口**"，前提正是这一层是纯函数；
3. `docs/02 §3.4` 的字段-需求对照表与 §10 的落点表，**也都以"判定可复算"为前提**。

> ★ **本节 2026-09-16 自 `docs/02 §7.2` 移入**（同一理由：模块图与依赖方向属于分层）。`docs/02 §7.2` 现只留一行指针。

### 5.3 N12 四解耦的架构断言

`docs/01` **N12（形态可扩展，MUST）** 要求"上下文来源、身份、事件、提示四者解耦，契约中不得写死'仅主站可用'的假设"。**把它落成可核对的一张表**（否则 N12 只是一句愿望）：

| 解耦对象 | 它在哪一层 | 换一个来源要改哪几个文件 | 契约里**不得**出现的假设 |
|---|---|---|---|
| **上下文来源** | `context` 是 `POST /api/chat` 的**显式可选参数**；值的来源由 `features/*` 提供 | **只改提供上下文的那一个 feature 文件 + 零契约改动** | 不得出现 `page-context` 这类主站专属契约（`ADR-0003` 决策 2 已删除该契约） |
| **身份** | `identity/` 的令牌解析 + `api/` 的依赖注入 | 新增一种身份来源 = **在 `identity/` 加一个解析器**，`api/` 与 `graph/` 不动 | 不得写死"会话只能来自本站 `localStorage`" |
| **事件** | `contracts/events.schema.json` 定义的 14 类事件 | 新增事件 = **加一类 + 前端按类型渲染**，不改传输 | 不得写死"事件只发给浏览器"（将来可能有别的消费者） |
| **提示** | `learning/` 的 `student_hint_log` **服务端计数** | 换提示策略 = 改 `domain` 的分级逻辑，**计数口径不变** | 不得写死"提示层级由客户端决定"（`docs/02 §7.1③` 已否掉这条） |

> ★ **N12 的验收方式就是这张表**：任何一处要更换的来源，改动都必须落在**表里写的那几个文件**之内。落在表外，就是契约里混进了主站专属假设。

## 6. 契约层在架构中的位置

**`contracts/` 不属于前端，也不属于后端，属于项目**（`ADR-0003` 决策 4）。它是**唯一一处前端与后端共同引用的形状定义**。

### 6.1 端口清单（**25 条 path**，2026-09-16 从 `docs/02 §6.1` 脚本数出；★ 2026-09-17 随 `GET /api/me/qa` 补入由 24 增至 25）

| 模块 | 端点 | 层归属 |

| 系统 | `GET /api/health` | `api/` + `core/`（只报本地事实） |

| 答疑 | `POST /api/chat` | `api/` → `graph/` → `tools/llm.py`（★ 唯一出网点） |
| 运行 | `GET /api/runs/{id}` · `POST /api/runs/{id}/hitl` | `api/` → `graph/`（run 是内存态，见 §9.3） |

### 6.2 producer / consumer 与兼容规则

| 项 | 规则 |
|---|---|
| **每份契约都要有 producer 与 consumer** | 不许有"没人产出"或"没人消费"的契约 —— 那是旧仓"最热的问答接口全无 schema、而冷门契约无人使用"的同一形态（`docs/01` 承诺 12） |

## 7. 扩展点四则

> 旧仓 `01-架构总览` 把「怎么新增一个 Agent」列为**最重要的扩展点**，机制是自研的**自动发现 + 规格模式**。v2 **不继承那个机制**（§10），改为"**显式注册 + 启动校验**"。

### ① 新增一个图节点

**★ 裁定（2026-09-16）：显式注册 + 启动校验。**

```
要动的地方 —— 恰好三处，一处都不能少：
  1. graph/nodes/<name>.py      实现。只做「取输入 → 调 domain|tools → 落事件」（§3.2 第 2 条）
  2. graph/registry.py          显式登记一行：注册名 · 入口函数 · ★ 该节点允许调用的工具集合
  3. backend/tests/             一个节点级用例
```

**启动校验（与 `docs/02 §8-14`「资产坏了就报错退出」同一模式，坏就起不来）**：

| 校验 | 不通过时 |
|---|---|
| 注册名重复 | **报错退出** |
| ★ 允许的工具集合为**空或通配** | **报错退出**（`docs/02 §1.6` 的 **R-Q ①**） |
| 入口函数不存在 / 签名不符 | **报错退出** |
| 注册表能导出「已注册清单」 | **启动时打印** —— 于是"谁被注册了"**可 grep、可断言**（这正是自动发现给不了的东西） |

> **为什么显式优于自动发现**：旧仓的 `kernel/registry.py` 靠扫描目录注册，结果是**名字冲突与漏注册只在运行时暴露**，且"到底注册了什么"无法 grep。本仓的原则二是"显式优于隐式"，而这条裁定就是它的第一个适用对象。

### ② 新增一个工具

```
  1. tools/<name>.py            实现（对外只出纯函数或薄适配；不 import api/ 或 graph/）
  2. graph/registry.py          在**允许调用它的节点**的集合里加上它（R-Q ①）
  3. backend/tests/             用例，含一条**失败路径**（R-Q ②③）
```

**★ 必须继承并修正旧仓的两条技术债（不是"重新写就好"，见 §9.2）**：

- **R-Q ①**：允许集合**不得为通配** —— 旧仓 `RunContext.use()` 写死 `allowed=None`，任何 Agent 都能调它没声明的工具；
- **R-Q ②③**：工具结果的 `ok` **必须来自真实执行结果**（旧仓 `tool.result.ok` 被硬编码为 `true`），且工具失败**必须进入事件流**，不得静默吞掉。

### ③ 新增一份契约

1. 先定 **producer / consumer**（§6.2），再写 schema —— 顺序不能反；
2. 在 `docs/04` 的清单里登记；
3. 若它承载新端点，`docs/02 §6.1` 的路由表要同步（否则 §6.1 与本篇 §6.1 的 25 条会对不上）。

### ④ 新增一个页面

```
  1. features/<x>/feature.json  id / route / 标题 / 顺序 / ★ class（必填）
  2. features/<x>/index.js · styles.css
  3. 本篇 §5.2 的页面清单加一行
  4. docs/05 的责任人表加一个人（一人一页）
  5. URL 必须可寻址（docs/02 §7.1 · N11）
```
