## 1. 责任人以「能力域」表示（★ 本文的一条口径决定）

**本文的责任人单位是「能力域」，不引入角色编号（`R1`…`R4`）。**

**为什么不用角色编号**：`R1` 在本套文档里**已经一词两义** ——

- `ADR-0001`/`0002`/`0003`/`0004`/`0005` 的"决策人"、`docs/03 §5.1` 的"谁写"列、`docs/04 §6` 的"契约唯一审批人"，用 `R1` 指**团队里的"架构 / 集成"这个位置**；
- `docs/01` 附录 B.2 的修订记录用"**评审 R1**"…"**评审 R11**"指**评审条目编号**（与需求 ID 是另一套体系，见该节末的说明）。

再引入一套 `R` 编号会加深这个歧义，而**歧义在"谁负责"这件事上代价最大**：一条规则找不到责任人时，人多半会以为"那是别的 R 的事"。

**既有写法怎么处理**：本文**不**逐一改写 `ADR-*` 与 `docs/03 §5.1`、`docs/04 §6` 里的 `R1` —— 那些是**历史记录与既有锚点**（ADR 不改是既定口径）。它们与本文的对应关系是：

| 既有写法 | 出现处 | 在本文里等同于 |
|---|---|---|
| `R1`（架构 / 集成 / 项目负责人 / 契约唯一审批人） | 五份 ADR 的"决策人"· `docs/03 §5.1` 的"谁写"列 · `docs/04 §6` | **架构与集成**域 |
| `R4`（前端） | `ADR-0001` 的"决策人：R1（架构）/ R4（前端）" | **前端页面与内容资产**域 |
| "四人小组" | `ADR-0001:89` · `ADR-0003:123` | ⇒ **一人一域**，见 §2.1 |

> ★ **代价（明账）**：责任人落在**域**而不是**人** ⇒ R-C 只能核到"**域有没有空缺**"这一层，核不到"今天是谁在写"。域内怎么分、谁请假谁接，**仍须小组自行指派** —— 这是"不用姓名"换来的代价，不是漏项。**四人小组 ⇒ 一人一域**，因此"域"与"人"在本项目里是**一对一**的，代价的实际大小取决于小组是否维持这个对应。

**分担情况：五类落在三个域上（前端页面与内容资产 2 · 后端与数据 2 · 编排与工具 1）⇒ 满足"至少两人"。**

> ★ **为什么"至少两人"必须写进规则，而不是"工作量可控"就够**（R-C 的理由，原样继承）：**F5 / F17 / F18 分别吃错因库 / 题型库 / 公式库** —— 三条需求对应**三条独立的产出流水**。压在一个人身上，这三条会在**同一天**一起挂（不是"慢一点"，是"同时红灯"）。上表的主责域特意让 **F5 → 后端与数据 · F17 → 前端页面与内容资产 · F18 → 编排与工具** 落在**三个不同的域**，就是为了让这三条流水**不共用一个瓶颈**。
> ★ **反对"缩小下界"**（决策 9A 已否决）：改下界是改 **MUST 级地板**，须走 ADR。**人力不够的正确解法是排期与分担，不是偷偷降低地板。**

1. ★ **跨域改动 = 先改责任人，再改代码**：一处改动要动到别人的目录时，**不许直接改**；要么由该域的人来改，要么在提交信息里写明"经 `<域>` 同意"（`docs/06` 的阶段门不核这一条，靠 §7 的 review 纪律）。

3. ★ **`docs/03 §2` 说"本节列出的目录才算存在的东西"**：因此新增目录 = **先改 `docs/03 §2`，再建目录，再来本表加一行**。跳过第一步就会出现"仓库里有东西，但骨架表不承认它"。

| 阶段 A（现在） | 下界与文件格式已定（`docs/02 §3.3` · 契约 C13） | — |
| ★ **阶段门 B 入口** | 五类的**首版**均达到下界，`content_rev` 可由门禁复算（`docs/04 §7` 校验⑥） | §2.2 的五个主责域，**架构与集成**域负责 `MANIFEST.json` 与复算 |
| ★ **阶段门 B 出口** | 资产的**回归基线**录入并冻结（判定准确率 / 解题正确率，`docs/01 §6`） | 后端与数据域录入，**非实现者**核 |
| 阶段 C | 冻结正式集的盲测在这批资产上执行（`eval_verify.py --frozen-dir`） | §6 的两人隔离 |

> ★ **为什么资产产出必须绑在阶段门 B，而不是"随时"**：F5 的**地板**（错因命中率 ≥ 90% 且每类 ≥ 4/5）**只能在资产齐备后测**。资产没到位，"F5 达标"就是一个**测不出来的断言** —— 那正是承诺 1 记的旧仓形态："代码走了流程，却一步真验证都没做"。

## 6. 两人隔离（N13 的盲测前提）

**`docs/01 §6` 的代价已记账，这里写的是它的分工形式**：

| 角色 | 谁 |
|---|---|
| **出题人**（编写解答级注入集 / 冻结验证集 / 答案级注入集 / 期望判据表） | ★ **不得由判定链或验证链的实现者担任** |
| **判定 / 验证实现者** | 后端与数据域（判定）· 编排与工具域（验证） |
| **正式集执行与签署** | **非实现者**，阶段门 C 手工执行，**结果只能由非实现者签署** |

★ **硬约束（`docs/01 §6` 原文）**：**若判定引擎只有一人实现，此人不得参与出题。** 若排不开人，退路是降为"最小可行隔离"（出题人与实现人分开），**且必须走 ADR 说明为何放弃盲测** —— 不许静悄悄地做。

## 7. 协作与审批规则

| 项 | 规则 |
|---|---|
| **分支与提交** | 一主题一提交（提交信息写清**为什么**，与 ADR / 契约变更记录呼应）；`docs/01` 附录 B 的"编号是外部引用锚点"意味着提交信息里的需求 ID **不得重编** |
| **契约改动** | 走 `docs/04 §6` 的五步：提案 → **架构与集成域审批** → 破坏性变更写 ADR → 在 schema 内追加变更记录 → 同步 consumer 列与 `docs/07` 的主题登记 |
| **ADR** | 只在"推翻既有决策"或"改 MUST 级地板"时新增；**ADR 正文不改**，变更以 `§v2 增量` 节追加（既有做法） |
| **口径变更** | 任何**计数与措辞**的改动必须同步它的**唯一权威处**（`docs/07` 登记）—— 本轮 A5 花掉的三处失同步（path 24→25 · `code` 14→16 · MUST 23→28）全部源于"正文没跟表体走" |
| **review 的边界** | 可自动的规则（R-A…R-Q 中的多数）交给 `scripts/verify.sh`；**只有 R-C 与本表的 §3/§4 靠人核** —— 所以它们被做成了 §2.4 的五条清单 |
| **不改别人的目录** | 见 §3 规则 1 |
