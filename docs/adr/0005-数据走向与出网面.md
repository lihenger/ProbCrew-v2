# ADR-0005 · 数据走向与出网面（部署形态两档 · 受控托管 · 日志只记 ID 与动作）

- **状态**：已接受
- **日期**：2026-09-16
- **决策人**：项目负责人（R1）
- **相关**：`docs/01` **N16**（部署形态与端点可控）· **N17**（受控托管）· N14 · N15 · F10 · F16 · `docs/02` §1.3–§1.6 · §4.2.1 · §8 · ADR-0004（本 ADR 部分修订其决策 1）

---

## 背景

ADR-0004 把 v2 的数据口径从"离线 / 数据不出校"改为"**用户自持凭据 + 开放许可资源联网可达**"，并**主动放弃了"断网也能完整演示"这个保险**。

随后落定两件事：

1. **最终部署形态是远程服务器**，为学生提供在线服务 —— 因此学生数据**存在我们运营的服务器上**，"只落本地库"这句话**失去参照物**。
2. 上一轮的保密设计**结构没换**：它被追加在原结构上，于是散在五处、**三处互相直接矛盾**（`qa_log` 同时是 L2 且会外传，而分级表只能表达一个属性；`§6.3` 与 `§8` 对"语料缓存缺失"给出相反行为；`model_unavailable` 把"没配 key"与"网络不通"合并成一个 code，前端会把断网的用户推去填 key）。

---

## 决策

### 1. 部署形态两档（N16）

| 形态 | 可用配置档 | 断网 |
|---|---|---|
| **单机**（答辩 / 教师自用） | **P1 本机端点** · P2 远程端点 + 凭据 · P3 无凭据 | ✅ P1 下**完整演示（含答疑）** |
| **远程托管**（正式服务） | **P2 · P3**（★ **P1 一律拒绝**） | P3 下**不含答疑** |

**为什么远程托管下拒绝 P1**：学生填的 `loopback` 是**服务器**的 loopback —— 他既无正当性使用它，它又是一个真实的 SSRF 面。**端点由用户提供（N14），不存在部署级共享端点。**

### 2. 受控托管（N17）

学生数据**只存于我们运营的服务器**，不流向第三方（**除模型调用载荷**）。据此把三条既有需求的口径从"本地库"改写为"受控托管"：**N6** · **F16** · **审计保留裁定**的前提。

★ **必须主动说的话**：**"不外传"的准确含义是"不发往第三方模型服务"，不等于"数据不出学生设备"**。单机形态下两者重合，**远程托管下不重合**。

### 3. 出网面（恰好两个口）+ 载荷白名单

- **(A) 运行期模型调用** = `backend/app/tools/llm.py`（**唯一出网口**，R-K 的判定对象）。
- **(B) 预抓脚本** = `scripts/fetch_corpus.py`（**离线运行，不在服务运行期**）。
- **正向允许**：`query` · `context.text` / `refs` · 系统提示 · L0 资产片段。
- **反向禁止**：`user_id` / `username` / 令牌 / `attempt` / `mastery` / `qa_log` 历史 / 审计。
- **凭据作为认证头发给端点是 N14 的固有面**，由 R-M 兜底，**与载荷白名单分开陈述**。

### 4. 端点信任边界（SSRF）

预置供应商 + **loopback 例外仅单机形态且须显式勾选** + 强制 `https`（loopback 除外）+ **禁跟重定向** + 超时与响应体积上界；`/api/model/ping` 与 `/api/chat` **共用同一校验函数**。

### 5. `code` 拆分

`model_unavailable` 拆为 **`model_key_missing`**（引导设置页）与 **`model_unreachable`**（**可重试**，文案"网络或模型服务不可达"，**不得引导填 key**）；`model_key_invalid`(400) 与 `model_quota_exceeded`(402) 保持。

### 6. 日志与审计只记 ID 与动作（R-O）

**不得出现提问原文、学生答案、教材片段、凭据。** 日志目录定死 `backend/data/logs/`（轮转 10MB × 5）。

## 后果

**正面**

- **断网保险在单机形态下恢复**（P1 + 用户自备本机端点）—— 答辩现场不再是"没网就是零"。
- **外传成为用户的选择**：不想外传的学生可以用本机端点；想用大模型的用自己的 key。
- **去向可查**（`qa_log.egress` + `provider`），"数据去了哪"从声明变成可核对的数据。
- **"验收通过但数据仍在"的洞被堵上**（R-O）。

**代价（必须承认）**

1. **多一档要测**：单机 P1 是一个**必须排练的一件事**（要事先备好本机模型），否则现场才发现没有。
2. **本机模型的质量由用户承担** —— 我们不内置、不打包权重，N16 **不承诺"装上就能用"**。
3. **告知与删除边界多一个文案分支**（条件化：单机 P1 显示"不发往第三方"）。
4. **远程托管下"不外传 ≠ 数据不出学生设备"** —— 必须主动说，否则是对用户的误导。
5. **R-O 会约束排障习惯**：日志看不到内容，排障只能靠 ID 与动作串。

## 被否决的备选方案

| 方案 | 为什么不选 |
|---|---|
| **部署级共享端点**（管理员配一个，全体学生用） | 让远程服务下学生"打开就能用"，但**与 N14「用户自持凭据」直接冲突**，且额度与责任集中 |
| **恢复"模板填充"离线生成路径** | 它产出的是**低质但看起来完整**的答案；在"无凭据"已经是一个**用户可修**的问题时继续降级，会让"答疑不可用"这条清晰语义变模糊，且与 N2 张力大 |
| **内置/打包本地模型权重** | 让 P1 变成"装上就能用"，但要分发数 GB 权重、承担版本与许可管理，且与 N4（免安装）冲突。**`docs/01 §9` 显式列为不做** |
| **恢复 N3 式"一律不出校"** | 等于放弃联网，与已确认的产品口径冲突 |
| **维持现状**（不重构，只补几句） | 三个维度混装的表**表达不了"一物两属性"**，而 `qa_log` 恰好就是；矛盾会一直存在到实现期 |
| **日志记内容 + 加密 + 短保留** | 要引入密钥管理面与保留期机制 —— 与本仓已否决的"审计盐化"同类；且 F16 的读回清单仍会漏掉日志 |

## 可逆性

| 决策 | 可逆性 |
|---|---|
| 部署形态两档 | **高**：形态是配置，不是代码分支 |
| 端点纯用户级 / 无部署级共享端点 | **中**：将来要加共享端点，是**新增一档**（P0）而不是改写 P1/P2/P3 |
| 受控托管（N17） | **不可逆**（数据一旦落在我们的服务器上，这个事实不会因为改文档而消失） |
| 出网清单两个口 | **高**：新增口只需改 R-K 的白名单，且改动会被门禁拦下 |
| 日志只记 ID 与动作（R-O） | **中**：放开意味着 F16 的"删除干净"不再成立，须重新论证 |
