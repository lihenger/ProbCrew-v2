## 背景

在此之前的整个原型是**无账号**的：身份 = 浏览器本地生成的匿名 `session_id`，后端把它当数据归属键。旧仓的需求分析甚至把这一点当作已满足的非功能需求（"无 PII ✅"），页面规格也明确规定 `attempt.student_id` 填 `session_id` 同值。

现在要支持**多账号**与**两种角色**（学生 / 管理员），并让学生数据管理页可用。这个需求本身来自立项书（认领的"JWT 鉴权 + 角色权限矩阵 ❌"），所以是**主动推翻**先前"无用户系统"的口径，而不是遗漏。

---

## 决策

### 1. 身份只来自令牌，路径参数不再决定归属

- 登录：`POST /api/auth/login` → **服务端会话令牌**（不是 JWT）。
- 令牌：`secrets.token_urlsafe(32)`，**库里只存 sha256**，7 天有效。
- 请求：`Authorization: Bearer <token>`；除 `/api/health`、`/api/auth/login` 与静态资源外，全部端点要求登录。
- **旧路径**（`/api/wrong/{session_id}`、`/api/stats/{session_id}`）保留 URL 形状，但**忽略路径参数**，身份一律以令牌为准。

**为什么不用 JWT**：JWT 是无状态的，无法满足"重置密码 / 禁用账号后**立刻**失效"。课程场景里"老师把某个账号停掉"必须是即时生效的。

**为什么必须改路径参数**：旧实现把 `session_id` 当身份，实测 `GET /api/wrong/随便一个人` 返回 200，`GET /api/runs` 会明文列出**所有人**的提问原文。

### 2. 数据归属改为 `user_id`，老数据迁移到一个不可登录的历史账号

- 三张业务表加 `user_id`，并统一改为 `student_` 前缀（旧仓数据分级约束：L2 表必须可机械识别）。
- `student_mastery` 主键由 `(session_id, topic)` 改为 `(user_id, topic)` —— 同一个人换浏览器就是另一个 session，按 session 聚合会把掌握度拆成几份。
- 老数据全部归属到 `usr_history`（`username='history'`、**空哈希 + disabled**，任何密码都登不进去），迁完把老表改名保留一周。

### 3. 只能管学生，且不能自锁

- 管理端接口与 CSV 导入**都无法创建管理员**（`role` 写死为 student）；管理员账号只由种子流程（首次启动）或 `scripts/manage_users.py` 产生。
- 管理员不能禁用 / 删除自己。
- 看学生明细 / 导出 CSV / 删数据 / 重置密码 / 禁用 —— 全部写审计，**审计写失败即中止操作**。

### 4. 三条口径的连带修正

- **无 PII → 化名账号**：不采集学号 / 真实姓名；密码只存 bcrypt 哈希；数据只落本地库；提供"删除我的数据"入口。
- **作答记录**：`attempt.student_id` 与 `user_id` 同值（契约里的历史命名保留）。
- **既有测试与脚本跟着改**：原本匿名调用接口的测试统一走登录辅助；运维脚本增加密码参数。

---

## 后果

**正面**

- 补上了立项书要求的角色与权限矩阵；管理端能回答"学生有没有在学"。
- 顺带修掉三处实测泄漏：`/api/runs` 全量明文、`/api/wrong/{sid}` 越权、运行轨迹接口回传完整答案。
- 有了账号，`hint_used` 才真正可用作"是否在抄"的信号。

**代价（必须承认）**

1. **这不再是"无 PII"**。缓解：账号为化名、密码只存哈希、数据只落本地、提供删除入口。
2. **注入式探针不再"打开即用"**。它注入在第三方页面，`localStorage` 与主站不共享 → 学生要在探针里再登录一次。
3. **演示环境需要先建号**。首次启动自动创建种子管理员并把密码打印到启动日志；批量建号走管理接口或运维脚本。
4. **测试与脚本要跟着改**。

---

## 替代方案（为什么没选）

| 方案 | 为什么不选 |
|---|---|
| 继续匿名 + 共享口令 | 无法区分学生，管理端只能看到一堆互不相干的 session，`hint_used` 也无从归属 |
| JWT（无状态令牌） | 无法即时吊销；"禁用账号后旧令牌还能用"是硬伤 |
| Cookie 会话 | 跨域要 `SameSite=None; Secure`，本地 http 调试直接不通 |
| 自建用户表 + 明文 / 可逆加密密码 | 不可接受 |
| 引入 PostgreSQL + 成熟用户系统 | 对本项目规模是过度工程；SQLite + 自建小表足够，换实现只改存储层 |

## §v2 增量与偏离（2026-09-16）

**凡与上文冲突，以本节与 `docs/02-系统设计` 为准。**

| # | 项 | 旧仓（上文） | v2 |
|---|---|---|---|
| 1 | **老数据迁移** | 迁到 `usr_history`，老表改名保留一周 | **不做** —— v2 是全新库（ADR-0003 §1）。`usr_history` 与迁移脚本**不搬**；`user.schema.json` 去掉该特例 |
| 2 | **`student_id` 与 `user_id` 同值** | 契约里的历史命名保留，两列都读 | ★ **已改为删除（2026-09-16）**：v2 是新库、**不迁旧数据**，故该列**不再保留**（`docs/02 §3.2`）。**本文正文第 4 节"作答记录"那一句因此作废**；`contracts/` 里不得再出现该字段 |
| 3 | **删除范围** | 三张业务表 | **四张表** —— 新增**提示流水** `student_hint_log`（`docs/01` F16 · `docs/02` §3.1） |
| 4 | **审计在删除时的处置** | 未明确 | **已裁定：保留**（合规证据优先；账号已化名，脱敏后不可回溯）。同时要求删除动作本身写审计（`docs/02` §3.1 已裁定项 1） |
| 5 | **`hint_used` 的来源** | 客户端随作答上报 | **服务端权威** —— 由提示流水计数，客户端上报值一律忽略（`docs/01` F6 · `docs/02` §5.2）。理由：否则"用了 3 次提示才答对照实记"只是前端的一句声明，改 URL 或直接构造请求即可绕过 |
| 6 | **CSV 导入的边界** | "都无法创建管理员" | 更进一步：**只能建 student 角色，且不接受学号 / 姓名字段** —— 否则一个便利功能就能破掉 N6（`docs/02` §6.1） |

**另有两处 v2 新增的鉴权口径**（不在本文范围内，但属同一主题，避免两处漂移）：

- **登录失败的信息量不变量**：**密码通过之前，一切失败都是同一个 `401 bad_credentials`，且都烧等长的时间**。为此把"锁定 423"的检查挪到密码验证之后（旧仓把它放在验证之前，实测构成账号存在性枚举面）。
- **角色口径**：v2 的"管理员"**即教师角色**，教师可见性由管理页承担（`docs/01` F15 · §5）。
