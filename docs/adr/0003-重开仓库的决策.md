# ADR-0003 · 重开仓库：保留范围与重构边界

- **状态**：已接受
- **日期**：2026-09-16
- **决策人**：项目负责人（R1）
- **相关**：`docs/01-需求分析` §7 §8 · `docs/03-架构总览` · `docs/07-文档地图` · 旧仓 ADR-0001（免构建 ESM）· 旧仓 ADR-0002（账号体系与身份口径）

---

## 背景

旧仓（`ProbCrew`，308 个受版本控制文件 / 后端 12 979 行 Python / 前端 22 740 行 JS·CSS / 24 篇文档 / 11 份契约）在完成账号体系与前端共享内核之后，出现了三类难以在仓内修复的问题：

1. **文档冗余而核心缺失**：分工写了 3 篇（`04`/`17`/`19`）、计划写了 3 篇（`05`/`12`/`14`）、地图写了 2 篇（`18`/`15`/`11`），而**系统设计一篇都没有**。同一主题多处记载，导致**改一处必漏一处**，出现"文档与代码双向漂移"。
2. **结构错位把简单问题变复杂**：账号表塞在业务工具目录（`tools/accounts.py`）；`kernel/` 把基础设施（配置、事件）与编排（图、运行器）混在一处；前端为兼容"注入式探针"与"主站"两种形态，维护了一套**共享内核 + 纯 Python 打包器 + 等价性测试**（约 3 500 行 + 两个生成器），而探针本身在真实平台上的可行性（宿主页面 CSP）**从未被验证**（旧任务 D2 因缺少真实平台账号而长期挂起）。
3. **验证叙事与产品重心失衡**：协作可见类前端页面（轨迹/架构/助手）约 1 400 行，是前端最大代码块；而学生真正要用的功能页很薄。多智能体叙事本应服务评委（S4），却占据了产品表面。

同时，账号体系（后端）与页面样式层（CSS）经过实测验证、耦合度低、可整体搬走：

| 资产 | 体量 | 依赖 |
|---|---|---|
| 账号体系后端 | `accounts.py` 701 行 + `auth.py` 333 行 + 3 个 API 模块 + 4 个测试文件 + 3 个运维脚本 | **只依赖 `config`** —— 除 `me.py`/`_aggregate.py` 外不被领域层拖住 |
| 样式层 | `tokens.css` 57 + `app.css` 200 + `components.css` 265 + `pages.css` 273 行 | `tokens.css` 是唯一令牌源（`app.css` 内零个自定义属性定义） |

---

## 决策

### 1. 重开仓库，只保留"账号体系 + 样式层"，其余从零写

新仓 `probcrew-v2` 与旧仓**并存**（不同目录）。旧仓**冻结为只读历史**，不再修改，包括不添加"已迁移"提示。

**搬走的（逐字搬运 + 改 import 路径，逻辑零改动）**：

- 后端账号体系：存储层 · 鉴权内核 · 3 个 API 模块 · 迁入 `identity/`
- 前端账号相关：`core/auth.js` · 管理页 feature · `core/api.js` 的账号部分（裁剪）
- 样式层四件：`tokens.css` · `app.css` · `components.css` · `pages.css`
- 契约 `user.schema.json`
- 账号测试 4 个文件 **56 个用例**（作为搬运正确性的唯一判据）
- 运维脚本：`manage_users.py` · `migrate_to_accounts.py` · `dev_login.py`
- ADR-0001（免构建 ESM）· ADR-0002（账号体系口径）原样搬运

**重写的**：需求 / 系统设计 / 架构文档 · 前端外壳 · 领域层 · 编排层 · 检索层 · 全部功能页 · 契约层其余部分。

### 2. 只做主站，注入式探针后置

探索针（读屏、划词、驱动动画）**不在 v2 范围内**。随之删除：`widget/` 约 3 500 行 · `shared/` 共享内核 · 两个生成器（`build_widget.py`/`gen_events_js.py`）· 探针专用测试 · 旧仓"前端技术栈口径"中大半篇幅。

**但"后置"不等于"放弃"**：由需求 **N12（形态可扩展）** 约束 —— 上下文来源、身份、事件、提示四者必须解耦，契约中不得写死"仅主站可用"的假设。因此探针将来是**新增**而不是**重写**。

**代价必须记账**：探针原本服务 S1（正在写作业的学生）。只做主站意味着 **S1 在 v2 里没有被完全服务**（`docs/01` §1 已如实标注）。

### 3. 保留 LangGraph

编排仍用 LangGraph 作为状态机运行时。旧仓的编排本就是自研的自动发现 + 规格模式，LangGraph 只提供图运行时与检查点；保留它可避免重踩中断恢复与状态持久化的坑。

**随之产生的风险见下 §风险**。

### 4. 目录横向分层，修正旧仓三处错位

```
contracts/           契约层（不属于前后端，属于项目）
backend/app/
  core/              基础设施：配置 / 错误 / 日志
  identity/          ★ 账号体系（从 tools/ 提出来）
  domain/            纯领域：分布 / 判分规则（无 IO、无 FastAPI、无 LangGraph）
  learning/          学习留痕：问答流水 / 作答记录 / 掌握度
  api/               路由层，必须薄
  graph/             LangGraph 编排（从 kernel/ 提出来）
  tools/             可被编排调用的工具：检索 / 向量 / 重排
frontend/{core,components,features,styles}
docs/  scripts/  backend/tests/
```

依赖方向由脚本检查，不靠自觉：`domain` 只依赖 `core`；`api` 必须薄；业务逻辑不得写在路由层或图节点函数里。

### 5. 表名不动，改的是代码归属

L2 敏感表**保留 `student_` 前缀原样**（`student_user` / `student_token` / `student_audit` / `student_qa_log` / `student_attempt` / `student_mastery`）。

理由：该前缀的唯一目的是让"一条 `LIKE 'student_%'` 排除全部敏感表"成立（旧仓 `docs/13` §1.1 约束 2）。**前缀是数据分级口径，目录是代码归属口径** —— 两者严格分开，因此把存储层拆到 `identity/` 与 `learning/` **不会**破坏这条安全属性。

### 6. 文档先行，一主题一篇

v2 的文档集固定为 **8 篇 + ADR**：`README` · `01 需求分析` · `02 系统设计` · `03 架构总览` · `04 契约层说明` · `05 分工与协作规范` · `06 开发计划与阶段门` · `07 文档地图`。
旧仓 24 篇按主题**合并**进这 8 篇，`docs/07` 登记"每个主题的唯一权威"。**任何主题不得有两处记载** —— 这是防漂移的机制，不是整理癖。

### 7. 契约补齐六处缺口

旧仓 11 份契约里，**最热的问答接口、统一错误体、分页、作答、掌握度、问答流水全无 schema**，每端各写各的形状。v2 契约 13 份，补齐 `error` · `pagination` · `chat` · `qa-log` · `mastery`，并删除随探针后置而作废的 `page-context`。

## 后果

**正面**

- 从零重写系统设计与架构，补上旧仓**从未有过**的核心文档。
- 删掉探针与共享内核后，前端代码量与复杂度大幅下降；**单一形态不需要生成式产物**。
- 文档从 24 篇降到 8 篇，且每个主题唯一权威，"改一处漏一处"的结构性风险消失。
- 账号体系与样式层是**已被实测验证**的资产，搬运不引入新设计风险；56 个测试用例是搬运正确性的判据。

**代价与代价控制**

| 代价 | 控制手段 |
|---|---|
| 编排层约 2 700 行需"重构搬家"，是全长任务 | 拆成 6 块，每块**搬前旧仓绿、搬后新仓绿**；见 `docs/06` |
| S1 的即时诉求在 v2 里未被完全服务 | `docs/01` §1 明账记录；N12 保证接口不被写死 |
| LangGraph 依赖重（+3 个包） | 阶段 B **第一个动作**就是验证其在本地 Python 版本上可装可用 |
| 新仓与旧仓并存可能产生两处真相 | `docs/07` 写明"旧仓 = 历史，任何结论以 v2 为准" |
| 重开仓库的动机是"旧的乱"而非"需求变了"，可能把坏设计一起带过来 | `docs/03` 必须有一节"我们从旧仓**刻意不继承**什么"，逐条给理由；不接受"重新写就好"这类理由 |

## 被否决的选项

| 选项 | 否决理由 |
|---|---|
| **在旧仓上做"大扫除"** | 文档与结构的错位是**四处弥漫**的（一主题多篇 + 目录错位 + 探针与主站双形态），在已经 308 个文件、12 979 行代码的仓里逐处修复，改动面比新建更大，且每次修复都要在"旧约定仍被引用"的环境里做妥协 |
| **放弃 LangGraph，改纯 Python 编排** | 依赖可减 3 个，但中断恢复、状态持久化、条件边要自研；旧仓在这些坑上已经付过成本，不值得再付一次 |
| **保留探针（两形态并存）** | 需要维持共享内核 + 纯 Python 打包器 + 等价性测试，而探针的**根本可行性（宿主页面 CSP）从未验证**。为未验证的收益维持最高复杂度的一层，属反向投资 |
| **表名改为 `l2_*` 等中性前缀** | 收益仅为命名美观，代价是存储层与测试的大范围机械改动，且可能削弱"前缀 = 数据分级"的口径稳定性。**前缀不动** |
| **前后端彻底分离成两个包** | 四人小组维护成本高于收益；横向分层的层边界已足以承担写作用域互斥 |
| **纯本地不建 git 仓库** | 无历史即无回退，且 `docs/06` 的阶段门需要提交作为证据。已决定建本地仓库，远端推迟 |

## 可逆性

| 决策 | 可逆性 |
|---|---|
| 只做主站 | **中**：N12 已把探针作为"新增"预留；但删除的探针实现（约 3 500 行）需从旧仓移植回来，不是零成本 |
| 保留 LangGraph | **高**：编排层若按"薄接口 + 单一运行时"写，替换运行时的改动面局限在 `graph/` |
| 表名不动 | **高**：新库无数据负担，改前缀是纯机械操作 |
| 文档合集为 8 篇 | **高**：`docs/07` 可增篇；但**不得**恢复"一主题多篇" |
| 重开仓库 | **不可逆**（但旧仓完整保留，可随时回看） |

**本节用于消除 `ADR-0002` 与 `ADR-0003` 的作业标准差异** —— 前者有 §v2 增量，后者原先没有。

| # | 项 | 本 ADR 原文 | 现状 |

| 1 | **L2 表清单** | 决策 5 列出**六张**表（`student_user` / `token` / `audit` / `qa_log` / `attempt` / `mastery`） | **七张** —— 新增 **`student_hint_log`**（提示流水，`docs/01` F6 的服务端权威计数载体）。**决策本身未被违反**（新表仍带 `student_` 前缀），缺的只是这份清单没跟上 |

| 3 | **只做主站** | 决策 2 | 仍成立；`page-context` 契约不进 v2 |
| 4 | **内容资产路径** | 决策 4 给的是目录骨架 | 后经裁决改为**顶层 `content/`**（与 `contracts/` 并列），`backend/data/` 成为**纯运行时目录** ⇒ `.gitignore` 可 deny-by-default。**这是对决策 4 的细化，不是推翻** |
| 5 | ★ **数据分级与"数据不出校"** | 决策 5 的论证引用 L2 前缀安全属性；`docs/02` 当时把"数据不出校"作为 N3 一条 MUST | **N3 已废弃**（2026-09-16，见 **ADR-0004**）：v2 改为**用户自持凭据**，学生提问会发给第三方。**"L2 表必须带前缀、结构上不可能入仓"这条安全属性不变**（它管的是**本地库**），但 `docs/02 §1.3` 已新增**「外传」一级**，因为它**不在我们控制内** |
