## 1. 用户不是一个人，是四个

学生项目最常见的失败是**把"学生"当成一个人**。实际上有四类人的成功标准**互相冲突**，一个界面同时讨好必然撕裂。

| 角色 | 真实处境 | 他要的 | 他**不**关心 |
|---|---|---|---|
| **S1 正在写作业的学生** | 有 deadline，现在就要这道题怎么算；**已注册**（或愿花一分钟注册） | 快、准、步骤能抄 | 读说明书、配环境、等半天 |
| **S2 备考的学生** | 要的是"我哪里不会"，以及反复练 | 薄弱点定位、能重做、有进度 | 单题的漂亮讲解 |
| **S3 任课教师** | 关心学生是否**真在学**、会不会被代做 | 能否被我看见、能否证明有效 | 架构多先进 |
| **S4 项目组 / 评委** | 关心这事有没有技术含量、能不能讲清 | 可验证、可复现的数字 | 界面好不好看 |

**关键推论**：**S1 与 S2 的诉求方向相反** —— S1 要"最快拿到答案"，S2 要"让我自己想出来"。

> ⚠️ **本仓必须承认的两处代价**（这是明账，不是"以后再说"）：
>
> **代价一 · 形态**：上一个仓库用**两种形态**化解 S1/S2 的冲突（探针服务 S1，主站服务 S2）。本仓决定**先只做主站**，探针后置 —— 因此 S1 得不到"就着屏幕上那段话提问"。需求 F1 成立、形态后置（见 §7），由 **N12** 保证主站不会把探针的路堵死。
>
> **代价二 · 门槛**：v2 的**全部学习类接口都要求登录**（F15），**不设免登录例外**。因此 S1 的"零摩擦"诉求**不被服务** —— v2 的 S1 实为"**已注册**学生"。
> 这不是懒，是**与 §5 伦理约束的正面冲突**：F5 的错因诊断是最接近"作业代写器"的能力，我们选择**不给它零摩擦入口**；且 ⑥⑦ 的持久化本就必须先有稳定身份（N6）。
> **v2 站在伦理一侧，并把这一取舍如实记账** —— 将来若有人要开免登录车道，必须先推翻这条理由，而不是"顺手加个开关"。

### 1.1 需求 × 角色覆盖矩阵

把"谁被服务"从散文变成**可机械核对**的表。**"v2 交付"三档的含义**：

- **完整** —— v2 范围内按 §4 验收栏完整交付。

- **后置** —— 形态后置，`docs/06` 里不计完成（§7 的判定规则）。

## 2. 概率论这门课特殊在哪

换一门课（比如英语单词），需求会完全不同。四条性质直接决定产品形态：

| 性质 | 后果 |
|---|---|
| **答案几乎总是一个可验证的数值或表达式** | ★ **最大的机会**：正确性可以被机器证明。英语作文不行，历史论述不行，概率论行 |
| **但"过程"比"答案"重要** | 学生错的往往不是算错，而是**建模错**（把 P(A\|B) 与 P(B\|A) 搞反、漏掉完备事件组）。只给答案没用 |
| **错误高度模式化** | 贝叶斯方向颠倒、独立与互斥混淆、忽略 n 次试验的独立性……**错误种类有限且可枚举** —— 这使"错因库"成为一份**有限、可穷举、可版本化**的资产（首版规模见 §4 F20） |
| **知识点依赖关系强** | 不会条件概率就学不会贝叶斯；不会期望就学不会方差。**知识点是有向图，不是列表** |

**推论 1**：因为答案可验证，"**告诉你这个答案经过了几层验证**"能成为真卖点 —— 文科类工具做不到。
**推论 2**：因为错误模式化且有限，"**告诉你踩了哪个坑**"比"再讲一遍知识点"有效得多，而且要**从教材与教师经验整理即可，不需要任何学生数据**。
**推论 3**：因为依赖关系强，错题不能只记"这道题错了"，必须记"**这道题考了哪几个知识点**"，才能沿依赖图往上找根源。**这一条直接决定数据模型**。

## 3. 从"学生的一次挫败"倒推功能

不要列功能清单。跟着一次真实的挫败走一遍，功能会自己长出来。

```
场景：学生做到一道贝叶斯题，卡住了。

① 他不知道这题在问什么            → 需求 F17：题目能看懂 / 能结构化拆解
② 他隐约记得有个公式但想不起来     → 需求 F18：精准的公式/定理查找（不是泛泛讲解）
③ 他写了一个式子，不确定对不对     → 需求 F5：逐步判定，指出第一处错在哪
④ 他算完了，但答案是 0.99         → 需求 F4：即时批改 + 诊断"你把方向搞反了"
⑤ 他改对了，但不知道为什么对       → 需求 F10：解析 + 这一步的依据（教材出处）
⑥ 一周后他又错了同一类题           → 需求 F8：错题按知识点归类 + 能重做
⑦ 他连着错了三道贝叶斯题           → 需求 F9：沿知识依赖往上找，是不是条件概率就没懂
                                         需求 F11：给出复习路径，而不是"再练 10 道"
```

> **七个环节与需求 ID 一一对应**（横跨 ③④ 的 `F6 分级提示` 是伦理约束，见 §5；环节 ↔ ID 的完整性由此可被机械核对）。

**七个环节，缺一环闭环就断。** 其中 ⑥⑦ 与 ①–⑤ 是**两种不同类型的需求**：

- ①–⑤ 是**单次会话内**的需求 → 无状态、可随时丢弃
- ⑥⑦ 是**跨会话**的需求 → **必须有持久化的作答记录**

> ★ **这是全篇最重要的推论**：任何声称"伴学"的工具，如果没有持久化作答记录，它其实只是个"答疑工具"。
> **"学习"这个词承诺的是时间维度上的变化，而没有记录就没有变化可谈。**
>
> ⚠️ **但"记下来"只完成了一半**：⑥⑦ 需要的是 **F7（记录）** 与 **F8（跨会话读回）**，两者**同为 MUST**。
> 只要求记录、不要求读回，会精确复现旧仓的失败模式 —— 契约完备、链路挂起。
> **日记了但打不开，等于没记**（见 §8 承诺 2）。

## 4. 需求清单

级别：**MUST**（缺了产品不成立）· **SHOULD**（缺了明显变差）· **MAY**（锦上添花）。
**"验收方式"一栏必须是可断言的动作**，不是形容词。

### 4.1 功能性需求

| ID | 需求 | 级别 | 验收方式（可断言） |
|---|---|---|---|
| **F1** | 学生能**带着上下文**提问（当前在看的题目 / 知识点 / 教材片段） | MUST | 提问请求必须携带至少一个上下文标识；无上下文时接口**显式降级**而非静默 |
| **F2** | 系统能解题并给出**可读的逐步过程** | MUST | **结构断言**：步骤数 ≥ 3，且每步含 `{说明, 式子}` 两字段**非空**、可被脚本校验。**适用范围：只约束 solve 类解答** —— `explain` / `lookup` 意图的回答不受"步骤数 ≥ 3"约束（否则脚本会把讲解类回答当解答判）。**语义部分为人工抽样项**（非自动门禁）：2 名非作者各自复述一次，均能还原意图即通过，判读记录留档 |
| **F3** | 每条解答带**正确性声明**（这次验证到什么程度） | MUST | 每条解答都携带级别标签；**无标签不出结果**；前端渲染该标签（后端发了前端不看等于没发） |
| **F4** | 提交作答后**即时判定**，且**不依赖大模型往返** | MUST | 纯计算题端到端 < 1s；判定链路中无 LLM 调用（以调用计数断言） |
| **F5** | 判定错误时给出**针对性错因**，而非"答错了" | MUST | **命中路径**：在注入集上错因命中率达地板（见 §6）。**未命中路径**：如实说"未识别错因"，**不得编造错因** |
| **F6** | **分级提示**（先方向 → 再步骤 → 最后解析），且**每次提示计入记录** | MUST | 未提交前**不得**返回完整解析；每次提示使 `hint_used` 精确 +1，并能从错题本如实显示"这道题用了 2 次提示"。**`hint_used` 由服务端计数（提示流水），客户端上报值一律忽略** —— 否则改一下 URL 或直接构造请求即可绕过，§5 伦理约束就没有执行载体。**只改 URL 的提示层级不能让服务端认为已取过提示** |
| **F7** | 每次作答**留下结构化记录** | MUST | 记录含：题目、作答、对错、知识点、用时、提示次数、判定者、**标准答案快照 + 资产版本号**（与 F20 的可版本化对齐；否则题库改版后历史记录无法解释）。**"用时"（`duration_ms`）是客户端自陈值，不参与任何验收** —— 要可信用时需另建"作答开始"记录，v2 不做（已记账） |
| **F8** | 错题可按**知识点**归类，并支持重做（**跨会话读回**） | MUST | 能列出"贝叶斯类错了 3 道"并可发起重做；**刷新页面后仍能读到**。只写不读等于没记（§3） |
| **F9** | 知识点**依赖关系**可见，错误可沿依赖上溯 | SHOULD | 存在知识点 DAG；错误可上溯到前置知识点 |
| **F10** | 解答能**引用教材出处**（章节/片段），可核对 | SHOULD | 检索命中带出处；**无命中时如实说明"未找到出处"** |
| **F11** | 学生能看到**自己学到哪了**（进度 / 薄弱） | SHOULD | 存在进度视图，**数据源必须是作答记录**，不得用"问答条数"冒充学习进度 |
| **F12** | 可视化辅助（分布曲线、交互动画） | MAY | 动画可播放、分布图可交互 |
| **F13** | 多智能体协作过程**可见** | MAY | 协作轨迹可回放 |
| **F14** | **提示使用透明化**：能回答"这次学习用了多少次提示" | SHOULD | 存在自陈视图，**数据源同 F11**（作答记录），仅按 `hint_used` 聚合；**不采集任何额外个人信息**（服务 S3，零合规成本） |
| **F15** | **账号与角色**：学生 / **教师（管理员）**两种身份；学生只见自己的数据 | MUST | **未登录不得访问任何学习类接口（含提问与判定），不设免登录例外** —— 这是与 §1 S1 摩擦预算的正面冲突，v2 选择站在 §5 伦理约束一侧；学生 A 无法读到学生 B 的任何数据（越权测试）；**可见范围**：管理员可见本机范围内全体学生数据（教师视角由管理页承担），学生只见自己；管理员账号**由 CLI 创建**，接口不可创建管理员 |
| **F16** | 学生可**删除自己的数据** | MUST | 调用删除接口后，该用户在学习记录表中的行数为 **0**（读回断言，不是"没报错"），账号被脱敏。**删除范围：四张表**（问答流水 / **提示流水** / 作答记录 / 掌握度）**均为 per-user**（掌握度主键为 `(user_id, topic)`），**不存在独立的匿名聚合层** —— 因此删除 = 明细 + 该用户的聚合记录一并删除，**不保留任何可回溯到该用户的统计**。与 N6 口径一致。**接口形状在 A3 落进契约** |
| **F17** | 题目可**结构化拆解**（已知 / 所求 / 适用模型） | SHOULD | **结构断言**：三段字段**非空且可被脚本校验**；**第三段的候选模型必须来自 F20 的"题型与解法套路"资产**（`model_id` 须命中资产，**不得由模型现编**）；无法判定时**显式标注"未匹配模型"**，不得留空装懂。**语义部分为人工抽样项**：2 名非作者各自复述一次（协议同 F2） |
| **F18** | **公式 / 定理精准检索**（按名称或知识点定位，非泛泛讲解） | SHOULD | 输入定理名，返回唯一条目且带**适用条件**；无命中时如实说明 |
| **F19** | 作答记录**必带知识点标注**；知识点之间维护**依赖 DAG** | MUST | 每条作答记录的知识点字段**非空**；DAG 可导出且**无环**。这是**数据模型层**需求，与展示层的 F9 分开定级（理由见附录 B 变更记录） |
| **F20** | **内容资产可维护**：题库 / 错因库 / 知识点 DAG / 公式库 / **题型与解法套路** | MUST | **五类资产**各有**固定文件格式**且可**版本化**（自制资产入库；教材语料除外，见 N3）；**错因与公式条目必须关联具体知识点 ID**，**题型条目必须关联它所用的知识点 ID**（F17 的"适用模型"吃的就是这一份）；**题库条目必须带 `gradable` 标记**，未标记视为资产错误。**首版规模（下界，只许上调）**：题库 **≥ 30 道** · 知识点 DAG **≥ 40 节点且覆盖 ≥ 5 章** · 错因库 **≥ 40 条** · 题型 **≥ 15 类**。**无教师访谈时的降级来源**：教材"常见错误"章节 + 自编做题经验 —— 外部依赖**不构成阻塞** |

### 4.2 非功能性需求

| ID | 需求 | 级别 | 为什么对本项目特别重要 |
|---|---|---|---|
| **N1** | **正确性可验证**：错误答案必须被拦住或标注 | MUST | 唯一的技术差异化。学生无法判断对错，**误信的代价由学生承担**。验收必须是**结果指标**：注入 20 道已知错解（方向颠倒 / 漏完备组 / 单位错 / n 乘错各 5 道）→ 断言被标注存疑或降级者 **≥ 18 道（90%）**。"走了重算流程"是过程指标，**可以被满足而毫无效果**。**该地板只允许上调，下调必须走 ADR** |
| **N2** | **诚实**：做不到的事必须明说 | MUST | 标注级别与实际验证手段的**一致率必须 100%**；不得笼统说"已校验"。学习工具的信任是一次性的 |
| **N3** | **数据不出校**（可本地 / 局域网运行） | MUST | 教材版权 + 学生数据合规；也是"能否给老师看"的前提 |
| **N4** | **无需安装即用** | MUST | 决定实际使用率；S1 的耐心 ≈ 0。免构建、零 npm、离线可跑 |
| **N5** | **不篡改第三方平台**（只读，不点击、不注入视觉元素） | MUST（条件） | 仅当将来做注入式探针时生效。**即使探针后置，这条也不得从需求里消失** —— 否则将来会有人"顺手"实现成能操作页面 |
| **N6** | **化名账号、无 PII**：不采集学号/真实姓名；密码只存哈希 | MUST | 既满足 ⑥⑦ 的持久化，又不触发个人信息保护的合规门槛。数据只落本地库 |
| **N7** | **响应及时**：单题判定 < 1s，讲解首字 < 2s | SHOULD | 超时就退化成"去问搜索引擎"了。**判定延迟以 F4（MUST）为准，本栏不重复定级** —— 同一指标在两处定级，会让 `docs/06` 的取舍失去依据 |
| **N8** | **可访问、可读** | MUST | 三项**可机检**指标：对比度 ≥ 4.5:1 · 点击目标 ≥ 32px · 键盘可达且带语义标签。由前端冒烟测试断言（让 §8 承诺 7 真正进门禁）。**屏幕阅读器完整支持不在本项验收内**，见 §9 |
| **N9** | **可复现的效果数据**：能说"这一版比上一版好多少" | SHOULD | 对 S4。**没有基线，所有改进都无法证明** |
| **N10** | 多端可用（至少手机能看错题本） | MAY | 复习发生在碎片时间 |
| **N11** | **可寻址与可回退**：URL 能表达界面状态，浏览器返回键有效 | MUST | 这不只是可访问性问题，**是功能缺陷**：刷到第 3 步提示不能刷新、不能分享、不能回退。缺它，四个页面会各自发明一套状态管理 |
| **N12** | **形态可扩展**：上下文来源、身份、事件、提示四者**解耦**，契约中不得写死"仅主站可用"的假设 | MUST | 这是"探针后置"唯一的技术代价控制手段。**后置不等于放弃** —— 若把主站专属假设写进契约，将来做探针就是重写而不是新增 |
| **N13** | **评测资产为一等交付物** | MUST | **拆成两句**（口径澄清，理由与价格见 §6 表后）：① **样例集**（小、公开，3–5 题）与**运行器**入主仓并**纳入门禁**（本地 `scripts/verify.sh`；接远端后该脚本即 CI 入口），缺失即红灯 —— 负责**防退化**；② **冻结正式集**（注入集 20 道 + 冻结验证集 + **期望判据表**）由**非实现者**保管且**不入主仓**，在阶段门 C 由非实现者执行 —— 负责**能力验收**。理由：N1 是 MUST 而其验收**完全依赖**评测资产 —— 使能项比被支撑的需求低一级属自相矛盾（与 F8 提级同一逻辑） |

## 5. 一条需求层面的伦理约束（不是功能）

**F1–F6 做得越好，工具越接近"作业代写器"。** 这是需求内在的矛盾，必须在产品层面缓解：

| 缓解手段 | 机制 |
|---|---|
| **提示阶梯（F6）** | 默认先给方向，完整解析需学生先尝试 —— 把"抄答案"变成"要点两下"的摩擦 |
| **不做"直接出最终答案"的入口** | 把"结论"放在"过程"之后 |
| **教师可见（F15 的教师角色，经管理页）** | 让 S3 知道工具在干什么，而不是被绕过 —— 落点是**已落地的管理页**（班级统计 / 学生明细），不是待建报表；F14 的学生自陈视图是同一目的的补充视角 |
| **如实记入掌握度** | "用了 3 次提示才答对"照实记。数据上不美化 —— **这正是 `hint_used` 字段存在的理由** |

> ★ 推论：**"提示阶梯"不是体验优化，是伦理约束落地的地方。** 它必须在数据模型里有对应字段（用了几次提示），否则约束**无法执行、也无法度量**。
> 这条把 F6 从"交互设计"提升为"必须产生数据的需求"。

## 6. 什么算"做成了"——成功标准

| 维度 | 对应需求 | 达标线 | 怎么测 |
|---|---|---|---|
| 解题正确率 | F2 · F17 | 在**冻结题集**上 ≥ **回归基线**（首次全量测量值，于阶段门 B 结束时录入本表并冻结；**只许上调，下调走 ADR**）。**这是回归门槛，不是质量门槛** —— 它防止退化，不假装我们知道绝对水平 | 固定题集 + 固定评分脚本（测量条件见"判定准确率"行） |
| 判定准确率 | F4 | 在**冻结题集**上、**单用户本地**、**进程已启动且首次请求已完成**的条件下：数值题 100%（确定性代码）；应用题允许表达误差 | 对照标准答案 |
| **判定延迟** | F4 · N7 | 纯计算题端到端 < 1s；判定链路中**无 LLM 调用** | 计时 + 调用计数断言（延迟定级以 F4 为准，N7 不重复定级） |
| **讲解首字** | N7 | 讲解首字 < 2s | 计时（这一项才需要"缓存已热"的定义：**进程已启动 + 首次同类请求已完成**） |
| **错误拦截率** | N1 · N13 | 注入的已知错解 **≥ 18/20（90%）** 被标注存疑或降级，**且每类（5 道）须 ≥ 4/5** —— 防整体容错掩盖单类崩盘。**地板只许上调，下调走 ADR** | 冻结正式集，由**非实现者**执行（约束见下）；见 N1 |
| **错因命中率** | F5 · N13 | 同上 90%，**且每类 ≥ 4/5** | 在同一个注入集上统计；见 F5 |
| **诚实性** | F3 · N2 | 一致率 **100%** | **全量断言**（不是抽查）：对每条验证报告断言 `level ≤ 手段允许的上限`（无 `sympy_recompute` ⇒ A 不可达；无 `symbolic_equivalence` ⇒ B 不可达）**且** `conf ≤ cap(level)`（上限表见附录 A 待落地项） |
| **越权隔离** | F15 | 学生 A 无法读到学生 B 的任何数据（含聚合与导出） | 越权用例：以 A 的令牌访问 B 的资源 |
| **删除读回** | F16 | 删除后**四张表**中该用户为 **0 行**（读回断言，不是"没报错"） | 接口测试 |
| **提示阶梯生效** | F6 | 未提交前**不返回**完整解析；每次提示使 `hint_used` 精确 +1 | 接口测试 |
| 闭环完整性（MUST 部分） | F4 · F5 · F7 · F8 · F19 | 全通（含 F8 能跨会话读到 F7 的数据） | 端到端走一遍并**刷新页面**（只写不读不算通） |
| 闭环完整性（SHOULD 环节） | F9 · F10 · F11 · F17 · F18 | 若缺失，界面必须**显式降级**（"本次未拆分题目"/"未找到出处"/"未定位薄弱点"），**不得静默** | 端到端走查（专测缺环时的降级话术） |
| **可访问性** | N8 | 对比度 ≥ 4.5:1 · 点击目标 ≥ 32px · 键盘可达 | 前端冒烟测试断言（N8 为 MUST） |
| **复习有效性** | F7 · **F8** · F19 | 同一知识点**重做首次正确率**相对首次作答的提升。**只承诺"能从作答记录算出来"，不设百分比门禁**；样本不足时必须显示"数据不足"。**首次正确率的单位 = `(user, item)` 的第一次 attempt**，指标实际来自错题重做（`source=wrong_review`），故 F8 也是它的来源 | 从作答记录按知识点分组统计。**观察指标，不是验收项** —— 见下方说明 |
| 可用性 | N3 · N4 | 无 Key、无网、无安装可完整演示 | 断网演示 |
| 可寻址 | N11 | 任一界面状态可复制 URL 到新标签页还原；返回键有效 | 手工走查 |

**两条对账规则**：

- **方向 A（防凭空）**：**§6 每个维度必须挂 ≥1 个需求 ID**，且该 ID 必须在 §4 存在 —— 挡住"冒出一个谁也没要求过的指标"。
- **方向 B（防漏项）**：**§6 不承担全覆盖责任**（它是对外证明，不是内部分解）；未进 §6 的 MUST 需求，必须在 [`06-开发计划与阶段门`](06-开发计划与阶段门.md) 有**独立**阶段门动作 —— 与附录 B 已有的规则合流，不新造机制。

**闭环两行的分级依据**（可机械核对 —— 环节的级别决定它落在哪一行）：

| 环节 | ① 题目拆解 | ② 公式检索 | ③ 逐步判定 | ④ 即时批改 | ⑤ 教材出处 | ⑥ 错题归类 | ⑦ 依赖上溯 + 进度 |
|---|---|---|---|---|---|---|---|
| 需求 ID | F17 | F18 | F5 | F4 | F10 | F8 | F9 · F11 |
| 级别 | SHOULD | SHOULD | MUST | MUST | SHOULD | MUST | SHOULD |

**MUST 行** = ③ ④ ⑥ 三个 MUST 环节 + **F7**（记录前提）+ **F19**（数据支撑）。
**SHOULD 行** = ① ② ⑤ ⑦ 四个 SHOULD 环节。
> 规则：**MUST 达标线里不得混入 SHOULD 环节**（那会造成"用 SHOULD 支撑 MUST"，正是 G4 的形态）。级别一变，先看它该落在哪一行。

**记法禁令**：**禁止使用需求 ID 区间记法**（原"F1→F8 全通"已改为显式 ID 列）。
理由有二：① 与附录 B"编号是外部引用锚点、只增不改"冲突 —— 将来在区间内插入一条 MUST，会被**静默**算进闭环验收；② 与 §3 的七环定义不符 —— 七环是 ①F17 ②F18 ③F5 ④F4 ⑤F10 ⑥F8 ⑦F9+F11，**F1 并不在七环之内**。
（§3 里的**环节编号区间** ①–⑤ / ⑥⑦ 不受此禁令约束：它们不是需求 ID，见附录 C。）

**评测资产的三条独立约束（N13 的可执行形式）** —— 防"出题人与被评人是同一批人"：

1. **冻结验证集**：从题库切出，**出题记录不进实现人视野**（执行形式见下表）；
2. **版本号 + 冻结日期**：注入集与验证集都带版本；并设**分类地板**（每类 5 道须 ≥ 4/5），防止整体容错掩盖单类崩盘；
3. **阈值不得在看到结果之后调整测法**；评测资产由**非实现者**执行。

**N13 与"完全盲测"的相容解**（刻意记账，因为它有真实价格）：

| 资产 | 存放 | 谁执行 | 自动化 |
|---|---|---|---|
| **样例集**（3–5 题 + 期望结论） | **入主仓** | 本地门禁（接远端后即 CI） | **自动红灯** —— 保住防退化价值 |
| **冻结正式集**（注入集 + 验证集） | **不入主仓**，非实现者保管 | 阶段门由非实现者手工执行 | **人工门禁，不能自动红灯** |
| **运行器** | **入主仓**（`scripts/eval_verify.py`，**不含任何答案**） | 任意人 | 可 review |
| **期望判据表** | 与正式集同处，**不入主仓** | 非实现者编写 | — |

> 为什么必须这样拆：**只要注入集进了仓库，实现人就能读到**，盲测失效；而离线、无密钥基础设施的前提下（ADR-0001），门禁无法从仓库外取题。**两者不能同时按字面成立** —— 拆成"样例集进门禁 + 正式集人工门禁"是唯一相容解。
> **为什么把"评分脚本"拆成"运行器 + 期望判据表"**：运行器本身**必须可 review** —— 否则没法确认它真的在数命中，而不是在数"没报错"。把**机制**留在仓库、把**答案**移出仓库，两个目的同时达成。
> **价格已记账**：N1 的正式验收**不能自动化**；需要**至少两人不可互换**（出题人 ≠ 判定/验证实现人）；若判定引擎只有一人实现，**此人不得参与出题**。若将来排不开人手，退路是降为"最小可行隔离"（出题人与实现人分开），届时须走 ADR 说明为何放弃盲测。
> **注入集口径（本轮定死）**：**注入物 = 系统错解**（一道题 + 一个**已知错误的解答**），**不是学生错解**；**注入点 = 验证链的输入**（函数级、确定性、可批量）；**断言 = 该解答被标注"存疑 / 不一致"或级别被降**。**明确不走 `/practice/grade`** —— 走纯判定链路时任何错答案本来就会被判错，门禁会**平凡通过**，那正是 N1 自己警告的"可以被满足而毫无效果"。分两层：函数级注入集 20 道（盲测、人工门禁）+ 端到端 3–5 道（样例集、进门禁）。

> **为什么"复习有效性"不设门禁**：它需要**同一个学生反复练同一知识点**才能算出，而样本量取决于真实使用，不由我们决定。
> 因此本文只承诺**能力**（能算出来）与**诚实**（算不出时显示"数据不足"），不承诺**数值**。把它设成门禁只会逼出一个假数字 —— 那正是 N2 要防的事。
> **代价已记账**：它不是承诺，只是能力。

**两条建仓规则**（承诺 8、9 的落地形式，进 `scripts/verify.sh` 自动扫描）：

- **R-A**：所有请求体中的字符串字段**必须**显式设上界（`max_length`）；判定类正则**禁止嵌套量词**。
- **R-B**：任何写库函数**必须**显式提交；对应测试**必须**读回断言，不得只断言"HTTP 200"。

**一条人力规则**（**脚本查不了，只能靠人** —— 正因如此更要写下来）：

- **R-C**：内容资产（**F20**）与编排层（`graph/`）**各须有明确责任人**，`docs/05` 的责任人表**不得留空位** —— **空缺即该需求不得计为已立项**。
  为什么它值得单列：旧仓把这五类资产明确写为"需要自制，工作量可控，但**没人能替你写**"，而当时的任务书里**没有任何一处**为它们指定人。结果就是"要求它存在，但没人造它"。

## 9. 本仓不做（明确边界）

**v2 永久不做**：npm / 打包器 · ORM · Postgres · Docker 化生产部署 · i18n · 多端适配（N10 为 MAY）。
**v2 本阶段不做（形态后置）**：注入式探针（读屏） · 划词交互 · 驱动宿主动画 · PDF 阅读器与教材溯源定位。
**v2 不做（数据门槛仍在）**：**跨用户聚合**与**教师侧建模分析**（成绩分析报表 / 掌握度热力图 / 跨班对比）—— 这些依赖真实学生数据与知情同意，**与"作答记录"是两件事**（见承诺 2，别再混为一谈）。
**本条的边界（必须写死，否则会重演旧仓的失败模式）**：本条**仅**指跨用户聚合与教师侧建模；**仅本人可见**的作答记录、掌握度与进度视图属 **F11 / F14 / F19，不受本条约束**。本机范围内的学生明细查看由管理页承担（F15 的教师角色）。
> 为什么这条边界必须写出来：旧仓的作答记录契约正是"因被归入需知情的建模线而**整体挂起**"，而错题本要的正是它。下一个接手者完全可以说"F11 的薄弱视图就是学习者建模"，然后整条线停摆 —— 这句话就是防这个读法的。
**v2 不做（无验收项）**：屏幕阅读器完整支持 —— 语言层输出无法机检，写进 MUST 会变成一扇永远红的假门禁，写 SHOULD 又假装将来会做。**不做就是不做**（见 N8）。

## 附录 A · 需求与数据的对照规则（防"由界面反推数据模型"）

数据模型**不是**"页面要显示什么就加什么字段"。
**规则**：字段-需求对照表放在 [`02-系统设计`](02-系统设计.md)，且必须满足两条：

1. **每个字段能指出它支撑哪个需求 ID** —— 说不出的**删掉**；
2. **每条 MUST 需求至少被一个字段或一个接口支撑** —— 说不出的**补上**。

> 上一个仓库的 6 处需求缺口，正是"先画界面、后凑字段"的产物。这条规则的成本接近于零，但它是唯一能挡住那种漏法的机制。

**必须在 A3（`docs/03` + `contracts/`）指定数据侧落地位置的需求** —— 避免需求里写"写入契约"而契约里查不到：

| 需求 | 要落进契约的东西 |
|---|---|
| **F15** | 账号与角色的字段定义、越权语义（学生不得读到他人数据） |

## 附录 B · 需求 ID 的变更规则

- **只增不改**：已有 ID 的含义不得改变；需求变了就新增 ID，旧 ID 标注"已被 Fxx 取代"并注明日期。
- **不重编号**：编号是外部引用锚点（`docs/06` 阶段门、测试用例名、提交信息都会引用）。
